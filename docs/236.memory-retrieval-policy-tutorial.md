> 长期记忆不是每轮都全部召回。好的检索策略先判断是否需要，再按用户、类别、过期和相关性逐层过滤。检索的目标不是"找到最多"，而是"在 token 预算内找到最有用的"。

## 它解决什么问题

```text
问题场景：

用户 Alice 有 200 条长期记忆。
当前对话："帮我写一个 FastAPI 接口"

如果全部召回：
- 200 条 × 50 token = 10000 token
- 上下文放不下
- 大量不相关（"用户喜欢咖啡"和写代码无关）

如果不检索：
- Agent 不知道用户偏好
- 可能用 tab 而不是用户喜欢的 space
- 可能给详细解释而不是用户喜欢的简洁风格

如果只按时间排序取最新：
- 可能取到"昨天讨论了天气"
- 而不是"用户偏好 4 空格缩进"

正确做法：
1. 判断是否需要检索（简单问候不需要）
2. 确定检索范围（偏好 + 和当前话题相关的）
3. 按相关性排序
4. 在 token 预算内取 top-N
5. 格式化注入上下文
```

## 核心概念

```text
检索策略的四层漏斗：

┌─────────────────────────────────────────────────┐
│  Layer 1: 触发判断 (Trigger)                     │
│  - 是否需要检索？                                │
│  - 简单问候 → 不需要                            │
│  - 复杂任务 → 需要                              │
│  - 通过率：~70%                                 │
├─────────────────────────────────────────────────┤
│  Layer 2: 范围确定 (Scope)                       │
│  - 检索哪些类别？                                │
│  - 偏好：总是检索                               │
│  - 事实：和话题相关时检索                       │
│  - 经验：和任务相关时检索                       │
│  - 通过率：~50%                                 │
├─────────────────────────────────────────────────┤
│  Layer 3: 相关性排序 (Ranking)                   │
│  - 语义相似度                                   │
│  - 有效得分（重要度 × 置信度 × 新鲜度）         │
│  - 访问频率加权                                 │
│  - 通过率：~20%                                 │
├─────────────────────────────────────────────────┤
│  Layer 4: 预算截断 (Budget)                      │
│  - Token 预算内取 top-N                         │
│  - 按类别配额分配                               │
│  - 保证多样性                                   │
│  - 最终：5-15 条                                │
└─────────────────────────────────────────────────┘

检索触发条件：
- 新会话第一轮 → 总是检索（加载用户画像）
- 话题切换 → 重新检索
- 用户提到"上次""之前" → 检索经验
- 简单确认（"好的""谢谢"）→ 不检索
- 工具调用结果返回 → 不检索（用任务状态）
```

## 最小示例

```python
"""最小示例：基本的记忆检索"""
from dataclasses import dataclass, field
from enum import Enum
import math


class MemoryCategory(Enum):
    PREFERENCE = "preference"
    FACT = "fact"
    EPISODE = "episode"


@dataclass
class MemoryItem:
    content: str
    category: MemoryCategory
    importance: float = 0.5
    confidence: float = 0.5
    access_count: int = 0
    embedding: list[float] = field(default_factory=list)


@dataclass
class RetrievalResult:
    item: MemoryItem
    score: float
    reason: str


class SimpleRetriever:
    """简单检索器"""

    def __init__(self, memories: list[MemoryItem]):
        self.memories = memories

    def retrieve(
        self,
        query_embedding: list[float],
        max_items: int = 5,
        categories: list[MemoryCategory] | None = None,
    ) -> list[RetrievalResult]:
        results = []
        for mem in self.memories:
            # 类别过滤
            if categories and mem.category not in categories:
                continue
            # 计算综合得分
            sim = self._cosine(query_embedding, mem.embedding)
            effective = mem.importance * mem.confidence
            frequency = 1 + mem.access_count * 0.1
            score = sim * 0.5 + effective * 0.3 + frequency * 0.2
            results.append(RetrievalResult(
                item=mem, score=score, reason=f"sim={sim:.2f}"
            ))
        # 排序取 top-N
        results.sort(key=lambda r: r.score, reverse=True)
        return results[:max_items]

    @staticmethod
    def _cosine(a: list[float], b: list[float]) -> float:
        if not a or not b:
            return 0.0
        dot = sum(x * y for x, y in zip(a, b))
        norm_a = math.sqrt(sum(x * x for x in a))
        norm_b = math.sqrt(sum(x * x for x in b))
        if norm_a == 0 or norm_b == 0:
            return 0.0
        return dot / (norm_a * norm_b)


# 使用
memories = [
    MemoryItem("用户偏好简洁回答", MemoryCategory.PREFERENCE, 0.9, 0.95,
               embedding=[0.1, 0.2, 0.8]),
    MemoryItem("用户使用 Python 和 FastAPI", MemoryCategory.FACT, 0.8, 0.9,
               embedding=[0.7, 0.6, 0.3]),
    MemoryItem("用户喜欢 4 空格缩进", MemoryCategory.PREFERENCE, 0.7, 0.85,
               embedding=[0.2, 0.3, 0.7]),
    MemoryItem("上次解决了 Redis 连接池问题", MemoryCategory.EPISODE, 0.5, 0.7,
               embedding=[0.4, 0.5, 0.4]),
    MemoryItem("用户喜欢喝咖啡", MemoryCategory.FACT, 0.3, 0.6,
               embedding=[0.9, 0.1, 0.1]),
]

retriever = SimpleRetriever(memories)
query = [0.6, 0.5, 0.4]  # "写 FastAPI 接口"的 embedding

results = retriever.retrieve(query, max_items=3)
for r in results:
    print(f"[{r.score:.2f}] {r.item.content} ({r.item.category.value})")
```

## 工程化版本

```python
"""工程化版本：完整的检索系统"""
from __future__ import annotations

import logging
import math
import time
from dataclasses import dataclass, field
from enum import Enum
from typing import Any, Callable

logger = logging.getLogger(__name__)


# ─── 数据模型 ───────────────────────────────────────────────

class MemoryCategory(Enum):
    PREFERENCE = "preference"
    FACT = "fact"
    EPISODE = "episode"


@dataclass
class StoredMemory:
    """存储的记忆"""
    id: str
    user_id: str
    content: str
    category: MemoryCategory
    embedding: list[float]
    importance: float = 0.5
    confidence: float = 0.5
    access_count: int = 0
    last_accessed: float = field(default_factory=time.time)
    created_at: float = field(default_factory=time.time)
    tags: list[str] = field(default_factory=list)
    expires_at: float | None = None

    @property
    def is_expired(self) -> bool:
        if self.expires_at is None:
            return False
        return time.time() > self.expires_at

    def effective_score(self) -> float:
        age_days = (time.time() - self.last_accessed) / 86400
        freshness = 0.5 ** (age_days / 90)
        return self.importance * self.confidence * freshness


@dataclass
class RetrievalConfig:
    """检索配置"""
    max_total_items: int = 10
    max_tokens: int = 500
    category_quota: dict[str, int] = field(default_factory=lambda: {
        "preference": 5,
        "fact": 3,
        "episode": 3,
    })
    min_relevance_score: float = 0.3
    always_include_preferences: bool = True
    cache_ttl_seconds: int = 300


@dataclass
class ScoredMemory:
    """带分数的记忆"""
    memory: StoredMemory
    relevance_score: float
    effective_score: float
    final_score: float
    match_reason: str


# ─── 触发判断 ───────────────────────────────────────────────

class TriggerDetector:
    """判断是否需要检索"""

    SKIP_PATTERNS = [
        "好的", "谢谢", "嗯", "ok", "再见",
        "没问题", "可以", "行",
    ]

    TRIGGER_PATTERNS = [
        "上次", "之前", "以前", "记得",
        "我说过", "我提过", "我喜欢",
    ]

    def should_retrieve(
        self, message: str, is_first_turn: bool, topic_changed: bool
    ) -> bool:
        # 第一轮总是检索
        if is_first_turn:
            return True
        # 话题切换时检索
        if topic_changed:
            return True
        # 简单回复不检索
        if message.strip() in self.SKIP_PATTERNS:
            return False
        # 包含触发词
        if any(p in message for p in self.TRIGGER_PATTERNS):
            return True
        # 默认：消息长度 > 20 时检索
        return len(message) > 20


# ─── 相关性计算 ─────────────────────────────────────────────

class RelevanceScorer:
    """相关性打分"""

    def __init__(
        self,
        semantic_weight: float = 0.5,
        effective_weight: float = 0.3,
        frequency_weight: float = 0.2,
    ):
        self.semantic_weight = semantic_weight
        self.effective_weight = effective_weight
        self.frequency_weight = frequency_weight

    def score(
        self, memory: StoredMemory, query_embedding: list[float]
    ) -> ScoredMemory:
        # 语义相似度
        sim = self._cosine(query_embedding, memory.embedding)

        # 有效得分
        effective = memory.effective_score()

        # 频率得分（归一化）
        freq = min(1.0, memory.access_count / 20)

        # 综合得分
        final = (
            sim * self.semantic_weight
            + effective * self.effective_weight
            + freq * self.frequency_weight
        )

        return ScoredMemory(
            memory=memory,
            relevance_score=sim,
            effective_score=effective,
            final_score=final,
            match_reason=f"sim={sim:.2f},eff={effective:.2f},freq={freq:.2f}",
        )

    @staticmethod
    def _cosine(a: list[float], b: list[float]) -> float:
        if not a or not b or len(a) != len(b):
            return 0.0
        dot = sum(x * y for x, y in zip(a, b))
        norm_a = math.sqrt(sum(x * x for x in a))
        norm_b = math.sqrt(sum(x * x for x in b))
        if norm_a == 0 or norm_b == 0:
            return 0.0
        return dot / (norm_a * norm_b)


# ─── 预算分配 ───────────────────────────────────────────────

class BudgetAllocator:
    """Token 预算分配"""

    def __init__(self, config: RetrievalConfig):
        self.config = config

    def allocate(
        self, scored: list[ScoredMemory], token_counter: Callable[[str], int]
    ) -> list[ScoredMemory]:
        """在预算内选择最优子集"""
        # 按类别分组
        by_category: dict[MemoryCategory, list[ScoredMemory]] = {}
        for s in scored:
            cat = s.memory.category
            if cat not in by_category:
                by_category[cat] = []
            by_category[cat].append(s)

        # 每类别内按分数排序
        for cat in by_category:
            by_category[cat].sort(key=lambda s: s.final_score, reverse=True)

        # 按配额选取
        selected: list[ScoredMemory] = []
        total_tokens = 0

        for cat_name, quota in self.config.category_quota.items():
            cat = MemoryCategory(cat_name)
            items = by_category.get(cat, [])
            count = 0
            for item in items:
                if count >= quota:
                    break
                tokens = token_counter(item.memory.content)
                if total_tokens + tokens > self.config.max_tokens:
                    break
                if item.relevance_score < self.config.min_relevance_score:
                    if cat != MemoryCategory.PREFERENCE:
                        continue
                selected.append(item)
                total_tokens += tokens
                count += 1

        # 最终按分数排序
        selected.sort(key=lambda s: s.final_score, reverse=True)
        return selected[:self.config.max_total_items]


# ─── 核心检索器 ─────────────────────────────────────────────

class MemoryRetriever:
    """记忆检索器"""

    def __init__(
        self,
        config: RetrievalConfig | None = None,
        trigger: TriggerDetector | None = None,
        scorer: RelevanceScorer | None = None,
        token_counter: Callable[[str], int] | None = None,
    ):
        self.config = config or RetrievalConfig()
        self.trigger = trigger or TriggerDetector()
        self.scorer = scorer or RelevanceScorer()
        self.allocator = BudgetAllocator(self.config)
        self._token_counter = token_counter or self._default_count
        self._cache: dict[str, tuple[list[ScoredMemory], float]] = {}
        self._stats = {
            "total_queries": 0, "skipped": 0,
            "cache_hits": 0, "retrievals": 0,
        }

    def retrieve(
        self,
        user_id: str,
        query: str,
        query_embedding: list[float],
        all_memories: list[StoredMemory],
        is_first_turn: bool = False,
        topic_changed: bool = False,
    ) -> list[ScoredMemory]:
        """执行检索"""
        self._stats["total_queries"] += 1

        # Layer 1: 触发判断
        if not self.trigger.should_retrieve(query, is_first_turn, topic_changed):
            self._stats["skipped"] += 1
            return []

        # 缓存检查
        cache_key = f"{user_id}:{query[:50]}"
        if cache_key in self._cache:
            cached, ts = self._cache[cache_key]
            if time.time() - ts < self.config.cache_ttl_seconds:
                self._stats["cache_hits"] += 1
                return cached

        # Layer 2: 用户隔离 + 过期过滤
        user_memories = [
            m for m in all_memories
            if m.user_id == user_id and not m.is_expired
        ]

        # Layer 3: 打分
        scored = [
            self.scorer.score(m, query_embedding)
            for m in user_memories
        ]

        # 过滤低分
        scored = [
            s for s in scored
            if s.final_score > self.config.min_relevance_score * 0.5
        ]

        # Layer 4: 预算分配
        result = self.allocator.allocate(scored, self._token_counter)

        # 更新访问记录
        for s in result:
            s.memory.access_count += 1
            s.memory.last_accessed = time.time()

        # 缓存
        self._cache[cache_key] = (result, time.time())
        self._stats["retrievals"] += 1

        return result

    def format_for_context(self, results: list[ScoredMemory]) -> str:
        """格式化为上下文文本"""
        if not results:
            return ""
        lines = ["[用户记忆]"]
        for s in results:
            cat_label = {
                MemoryCategory.PREFERENCE: "偏好",
                MemoryCategory.FACT: "信息",
                MemoryCategory.EPISODE: "经验",
            }[s.memory.category]
            lines.append(f"- [{cat_label}] {s.memory.content}")
        return "\n".join(lines)

    @staticmethod
    def _default_count(text: str) -> int:
        chinese = sum(1 for c in text if '\u4e00' <= c <= '\u9fff')
        return int(chinese * 1.5 + (len(text) - chinese) * 0.3)

    def get_stats(self) -> dict:
        return dict(self._stats)


# ─── 使用示例 ───────────────────────────────────────────────
```

## 检索策略详解

```text
策略 1：Always-on 偏好检索
━━━━━━━━━━━━━━━━━━━━━━━━
- 偏好类记忆每轮都检索（数量少，价值高）
- 不需要语义匹配，直接取 top-5
- 缓存 5 分钟（偏好很少变）
- Token 成本：约 100 token

策略 2：Topic-aware 事实检索
━━━━━━━━━━━━━━━━━━━━━━━━
- 检测当前话题
- 只检索和话题相关的事实
- 例：讨论代码 → 检索技术栈、环境
- 例：讨论订单 → 检索地址、支付偏好

策略 3：Query-triggered 经验检索
━━━━━━━━━━━━━━━━━━━━━━━━
- 用户提到"上次""之前"时触发
- 或者当前问题和历史经验语义相似
- 用向量检索找最相关的经验
- 例：又遇到连接池问题 → 召回上次解决方案

策略 4：Progressive 渐进检索
━━━━━━━━━━━━━━━━━━━━━━━━
- 第一轮：只加载偏好（快）
- 对话深入：按需加载事实和经验
- 避免一次性加载太多
- 减少首轮延迟

策略 5：Negative 排除检索
━━━━━━━━━━━━━━━━━━━━━━━━
- 标记"不要检索"的场景
- 工具调用返回时（用任务状态）
- 纯确认消息（"好的""收到"）
- 系统消息（错误提示、状态更新）

组合使用：
- 新会话第一轮：策略 1 + 策略 4
- 正常对话：策略 1 + 策略 2
- 用户回忆：策略 1 + 策略 3
- 工具交互：策略 5（跳过）
```

```python
"""检索策略选择器"""
from enum import Enum
from dataclasses import dataclass


class RetrievalStrategy(Enum):
    PREFERENCES_ONLY = "preferences_only"
    TOPIC_AWARE = "topic_aware"
    QUERY_TRIGGERED = "query_triggered"
    FULL = "full"
    SKIP = "skip"


@dataclass
class StrategyContext:
    """策略选择上下文"""
    is_first_turn: bool
    topic_changed: bool
    has_trigger_words: bool
    is_tool_response: bool
    message_length: int
    current_topic: str


class StrategySelector:
    """策略选择器"""

    def select(self, ctx: StrategyContext) -> RetrievalStrategy:
        # 工具响应不检索
        if ctx.is_tool_response:
            return RetrievalStrategy.SKIP

        # 太短不检索
        if ctx.message_length < 3 and not ctx.is_first_turn:
            return RetrievalStrategy.SKIP

        # 第一轮：完整检索
        if ctx.is_first_turn:
            return RetrievalStrategy.FULL

        # 触发词：经验检索
        if ctx.has_trigger_words:
            return RetrievalStrategy.QUERY_TRIGGERED

        # 话题切换：话题感知
        if ctx.topic_changed:
            return RetrievalStrategy.TOPIC_AWARE

        # 默认：只检索偏好
        return RetrievalStrategy.PREFERENCES_ONLY
```

## 常见失败模式

```text
失败模式 1：检索不足
━━━━━━━━━━━━━━━━━━━━━━━━
症状：Agent 该用记忆时没用
原因：触发条件太严格
后果：用户体验不连贯
修复：
- 新会话第一轮必须检索
- 偏好类 always-on
- 降低触发阈值

失败模式 2：检索过度
━━━━━━━━━━━━━━━━━━━━━━━━
症状：每轮都检索大量记忆
原因：没有跳过逻辑
后果：延迟增加，token 浪费
修复：
- 简单回复跳过
- 工具响应跳过
- 缓存复用

失败模式 3：相关性差
━━━━━━━━━━━━━━━━━━━━━━━━
症状：检索到的记忆和当前话题无关
原因：只用时间排序，不用语义
后果：上下文被无关信息占满
修复：
- 必须用向量检索
- 综合得分（语义 + 重要度 + 频率）
- 设置最低相关性阈值

失败模式 4：类别失衡
━━━━━━━━━━━━━━━━━━━━━━━━
症状：全是偏好，没有相关事实
原因：没有类别配额
后果：缺少任务相关的关键信息
修复：
- 按类别分配配额
- 偏好 5 + 事实 3 + 经验 3
- 保证多样性

失败模式 5：缓存失效
━━━━━━━━━━━━━━━━━━━━━━━━
症状：用户更新了偏好，Agent 还用旧的
原因：缓存 TTL 太长
后果：信息过时
修复：
- 偏好缓存 5 分钟
- 写入时主动失效缓存
- 用户修改后立即刷新
```

## 什么时候不要这么做

```text
不需要复杂检索策略的场景：

1. 记忆少于 10 条
   - 全部放上下文就行
   - 不需要排序和截断

2. 只有偏好记忆
   - 偏好数量固定（5-10 条）
   - 直接全量加载
   - 不需要语义检索

3. 单轮交互
   - 没有"当前话题"概念
   - 一次性加载即可

4. 延迟极敏感
   - 向量检索有延迟
   - 可以用预加载代替实时检索

判断标准：
- 记忆 > 20 条？→ 需要检索策略
- 有多种类别？→ 需要配额
- 话题多变？→ 需要语义匹配
- 以上都不是？→ 全量加载即可
```

## 生产环境注意事项

```text
性能优化：

1. 预加载
   - 用户登录时预加载偏好到 Redis
   - 新会话第一轮直接从缓存取
   - 减少冷启动延迟

2. 向量检索优化
   - 按 user_id 分区（缩小搜索范围）
   - HNSW 索引（Qdrant/Milvus）
   - 量化：float32 → int8（4x 加速）

3. 缓存策略
   - 偏好：Redis 缓存 5 分钟
   - 事实：Redis 缓存 1 分钟
   - 经验：不缓存（每次语义检索）
   - 写入时主动失效

4. 批量检索
   - 一次查询多个类别
   - 合并向量检索请求
   - 减少网络往返

5. 降级策略
   - 向量库不可用 → 用缓存的偏好
   - 超时 → 返回空（不阻塞对话）
   - 部分失败 → 返回已成功的部分

延迟预算：
- 触发判断：< 1ms
- 缓存命中：< 5ms
- 向量检索：< 50ms
- 打分排序：< 10ms
- 总计 P95：< 70ms
```

```python
"""检索系统监控"""

   - skip_rate: 跳过率

   - recall: 该召回的有多少被召回

   - 延迟 P95 > 100ms → 性能问题
   - 使用率 < 30% → 检索质量差

5. A/B 测试
   - 有记忆 vs 无记忆的回答质量
   - 不同检索策略的用户满意度
   - 不同 token 预算的效果对比
"""
```

## 和 RAG / 后端 / 前端的关系

```text
与 RAG 的关系：
- 记忆检索和 RAG 检索共用向量库
- 可以合并为一次查询（记忆 + 文档）
- 区别：记忆按 user_id 隔离，文档是共享的
- 结果合并时记忆优先级高于文档

与后端的关系：
- 向量检索走向量库 API
- 缓存在 Redis
- 预加载用后台任务
- 降级逻辑在服务端

与前端的关系：
- 新会话首轮可能有额外延迟（预加载）
- 流式输出时先显示回答，记忆后台加载
- 调试面板显示"本轮使用了哪些记忆"
```

## 面试怎么讲

```text
面试官问：记忆检索怎么设计？

回答框架（2 分钟）：

"我用四层漏斗：触发、范围、排序、预算。

触发层判断要不要检索——
简单问候不检索，工具响应不检索，
新会话第一轮必须检索。

范围层确定检索哪些类别——
偏好 always-on，
事实和当前话题相关时检索，
经验在用户提到'上次'时检索。

排序层用综合得分——
语义相似度 50% + 有效得分 30% + 频率 20%。
有效得分是重要度 × 置信度 × 时间衰减。

预算层在 token 限制内取 top-N——
按类别分配配额：偏好 5、事实 3、经验 3。
保证多样性，不会全是同一类。

性能优化：
- 偏好预加载到 Redis
- 向量库按 user_id 分区
- 缓存 5 分钟
- 总延迟 P95 < 70ms

我踩过的坑：
一开始每轮都全量检索，延迟高且浪费。
后来加了触发判断和缓存，
70% 的请求不需要检索或命中缓存。"

追问应对：
Q: 怎么评估检索质量？
A: precision@5（top-5 中相关的比例）> 80%，
   加上用户满意度 A/B 测试。

Q: 向量库挂了怎么办？
A: 降级到缓存的偏好。偏好是预加载的，
   即使向量库不可用也能用。
```

## 设计原则总结

```text
检索策略的 7 条原则：

1. 按需检索
   - 不是每轮都需要
   - 触发条件明确
   - 能跳过就跳过

2. 偏好优先
   - 偏好 always-on
   - 数量少、价值高
   - 预加载到缓存

3. 语义为王
   - 必须用向量检索
   - 不能只按时间排序
   - 综合得分 > 单一维度

4. 预算硬限
   - Token 预算不可超
   - 按类别分配配额
   - 保证多样性

5. 快
   - P95 < 70ms
   - 缓存 + 预加载
   - 超时降级

6. 隔离
   - 按 user_id 严格隔离
   - 不跨用户检索
   - 过期记忆不参与

7. 可观测
   - 记录每次检索的输入输出
   - 追踪记忆被使用的比例
   - A/B 测试不同策略
```

## 检索质量调优指南

```text
调优步骤：

1. 建立基线
   - 收集 100 个真实查询
   - 人工标注"应该召回哪些记忆"
   - 计算当前 precision@5 和 recall

2. 调整权重
   - 语义相似度权重太低 → 召回不相关
   - 有效得分权重太低 → 召回过时记忆
   - 频率权重太低 → 高频记忆排不上来
   - 建议起点：0.5 / 0.3 / 0.2

3. 调整阈值
   - min_relevance_score 太高 → 召回不足
   - min_relevance_score 太低 → 噪声多
   - 建议起点：0.3

4. 调整配额
   - 某类经常用不到 → 减少配额
   - 某类经常被截断 → 增加配额
   - 监控各类的实际使用率

5. 迭代验证
   - 每次只调一个参数
   - 用标注集验证
   - A/B 测试用户满意度
```
