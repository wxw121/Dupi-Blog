### Q1. 什么是 TypeScript？在 从「JavaScript 加类型」到能读懂现代前端代码 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · TypeScript |

**参考答法（开发向）：**

**TypeScript**（类型脚本）：由微软维护的开源语言，语法是 **JavaScript 的超集**（superset）。

直觉：你写的 TS **几乎都可以当作 JS 来理解**——多出来的主要是**类型标注**和少数 TS 专属语法（如 、部分枚举写法）；最终给浏览器或 Node 跑的，仍是 **JavaScript**。

**工程语境（从「JavaScript 加类型」到能读懂现代前端代码）**：
- 解决什么：把「TypeScript」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- TypeScript 和容易混淆的替代方案怎么选？
- 如果去掉 TypeScript 这一层，最先坏掉的是哪一环？

### Q5. 生产环境 从「JavaScript 加类型」到能读懂现代前端代码 出现：**结论**：响应体用 + 守卫，或代码生成/OpenAPI 类型。… —— 排查思路是什么？ {#q5}

### Q12. 从「JavaScript 加类型」到能读懂现代前端代码 能力要上生产，你会优先保证哪三件事？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 从「JavaScript 加类型」到能读懂现代前端代码 常见风险点：典型场景：你从接口拿到用户对象，在页面里写 （把 拼错了）。JavaScript **不会**在保存文件时报错；页面渲染空白，你打开控制台才看见 ，再一层层 找拼写——这就是**动态类型**的日常代价：变量在**运行时**才暴露真实形状，编辑器只能猜。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
