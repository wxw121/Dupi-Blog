### Q1. 你怎么设计一个代码审查 Agent？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 系统设计 / 表述 |

**参考答法（开发向）：**

两层架构：规则引擎 + LLM。 规则引擎做快速静态检查（安全、风格），毫秒级。 LLM 做深度审查（逻辑、设计），只对可疑代码调用。 大 PR 分块处理，安全文件优先。 每条意见带严重级别、分类、具体建议。 只有 Critical 才阻塞合并，避免过度干预。 追踪误报率持续调优、允许开发者标记"不是问题"。 优先级：安全相关文件先审查。 跨文件检查：接口变更是否同步了调用方。 Agent 理解语义和逻辑（"这个 if 条件可能漏了边界"）。 Agent 能给设计建议，linter 不能。

**常见追问：**

- 怎么减少误报？ 白名单机制（# noqa）、路径过滤（测试文件跳过）、
- 大 PR 怎么处理？ 分块：每块最多 200 行 / 5 个文件。
- 和 linter 有什么区别？ Linter 检查语法和风格（确定性规则）。
