### Q1. 如何设计/实现「最小评测示例」？（DeepEval 入门指南） {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 最小评测示例 |

**参考答法（开发向）：**

**背景要点**：传统单元测试很擅长判断“函数输出是否等于某个值”。但 LLM 应用的答案往往不是固定字符串。你更关心的是：答案是否相关，是否基于上下文，是否遗漏关键点，是否包含有害内容。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；
2. **组件图**：列出 3～5 个模块及数据流（可手绘）；
3. **关键接口**：同步 API / 消息 / 批处理任务各负责什么；
4. **失败与降级**：超时、空检索、工具失败时的默认策略；
5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

- MVP 版本可以砍掉哪些部分？
- 10x 流量时最先改什么？

### Q8. DeepEval 入门指南 能力要上生产，你会优先保证哪三件事？ {#q8}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 DeepEval 入门指南 常见风险点：传统单元测试很擅长判断“函数输出是否等于某个值”。但 LLM 应用的答案往往不是固定字符串。你更关心的是：答案是否相关，是否基于上下文，是否遗漏关键点，是否包含有害内容。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
