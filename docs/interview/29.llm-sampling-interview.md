### Q1. 什么是 采样？在 Temperature / Top-p / Top-k 采样 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 采样 |

**参考答法（开发向）：**

**采样**（sampling）：按规则从分布里抽出一个 token，接到后面，再重复。

直觉：不是计算器按出唯一解，更像 **按权重抽签**——温度和 top-p/top-k 就是抽签规则。

**工程语境（Temperature / Top-p / Top-k 采样）**：

- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 采样 和容易混淆的替代方案怎么选？

### Q4. 什么是 Top-p？在 Temperature / Top-p / Top-k 采样 相关系统里它承担什么职责？ {#q4}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Top-p |

**参考答法（开发向）：**

**Top-p**（核采样 / nucleus sampling）：按概率从高到低累加，直到累计概率达到阈值 **p**（如 0.9），只保留这批「核心」token，再采样。

直觉：不固定人数，而是凑够 **前 p 的概率质量**——分布尖时可能只剩两三个词；分布平时常会纳入更多词。

**工程语境（Temperature / Top-p / Top-k 采样）**：
- 解决什么：把「Top-p」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；

### Q5. 生产环境 Temperature / Top-p / Top-k 采样 出现：1. **同时把温度、top-p、top-k 拧到极端** —— 无法归因，先只动一个。 2. **用高温「激发」模型遵… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：1. **同时把温度、top-p、top-k 拧到极端** —— 无法归因，先只动一个。 2. **用高温「激发」模型遵守复杂格式** —— 格式靠提示词与校验，不靠高温。 3. **忽略厂商默认值** —— 你没传参不等于「无随机」。 4. **把 top-p=0.9 理解成「只用 90% 的词表」** —— 实际是累计概率达到 0.9 的那批高概率词。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q9. 做 Temperature / Top-p / Top-k 采样 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 Temperature / Top-p / Top-k 采样 全链路。

**通常不在同一层硬做的**（示例）：
- ** Softmax 温度公式的完整推导、beam search 细节、投机解码、各厂商隐藏默认值的逐项审计。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

### Q13. Temperature / Top-p / Top-k 采样 能力要上生产，你会优先保证哪三件事？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Temperature / Top-p / Top-k 采样 常见风险点：大模型写答案时，并不是脑子里只有一个「标准下一个字」。每一步它会对词表里成千上万个 token 打出 **概率分布**——有的很像下一手，有的很离谱。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
