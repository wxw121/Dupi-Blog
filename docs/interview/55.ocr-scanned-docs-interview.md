### Q1. 什么是 OCR？在 OCR 与扫描件 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · OCR |

**参考答法（开发向）：**

**OCR**（光学字符识别）：把页面 **当图片看**，猜出上面的字。这篇是 企业 RAG 路线图 **C1 延伸**（路线图第 **62** 条，**加分档**），讲清文本层为空时的分支、OCR 直觉、Tesseract / 云 OCR 了解、质量坑、与 PyMuPDF 衔接，以及 **pytesseract** 最小示例（含环境说明）。前置：36 PDF 文本提取、42 PyMuPDF；清洗见 46 文本清洗。

**工程语境（OCR 与扫描件）**：
- 解决什么：把「OCR」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- OCR 和容易混淆的替代方案怎么选？
- 如果去掉 OCR 这一层，最先坏掉的是哪一环？

### Q9. 做 OCR 与扫描件 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 OCR 与扫描件 全链路。

**通常不在同一层硬做的**（示例）：
- ** CRNN/Transformer OCR 训练、版面分析模型微调、GPU 批量集群运维、手写体专用识别、多模态 VLM 读图（见路线图 **63** 56 篇）。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q13. OCR 与扫描件 能力要上生产，你会优先保证哪三件事？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 OCR 与扫描件 常见风险点：**静默失败**：chunk 为空，用户问条款 **检索不到**；

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
