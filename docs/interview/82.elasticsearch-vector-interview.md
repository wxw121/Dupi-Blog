### Q1. 如何设计/实现「ES 向量检索是什么」？（Elasticsearch 向量检索入门指南） {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · ES 向量检索是什么 |

**参考答法（开发向）：**

**背景要点**：很多企业已经用 Elasticsearch 做日志、文档和站内搜索。如果 RAG 文档也在 ES 里，加一个向量字段就能做语义检索，避免再引入新系统。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；

5. **评测**：离线指标 + 线上 shadow / 金丝雀。

### Q5. 生产环境 Elasticsearch 向量检索入门指南 出现：ES 向量检索的 FAQ 高度集中于 mapping 维度和分数尺度——前者导致写入失败或 silent 错位，后者导致… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：ES 向量检索的 FAQ 高度集中于 mapping 维度和分数尺度——前者导致写入失败或 silent 错位，后者导致混合检索时被某一路 dominate。遇到 kNN 无结果，先查 与 refresh，再查 filter 是否把库筛空。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q11. Elasticsearch 向量检索入门指南 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Elasticsearch 向量检索入门指南 常见风险点：很多企业已经用 Elasticsearch 做日志、文档和站内搜索。如果 RAG 文档也在 ES 里，加一个向量字段就能做语义检索，避免再引入新系统。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
