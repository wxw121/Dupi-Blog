### Q1. 什么是 ANN？在 FAISS 本地 ANN 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · ANN |

**参考答法（开发向）：**

**ANN**（Approximate Nearest Neighbor，近似最近邻）：不保证找到 **全局** Top-k，但在高维空间里用 **聚类、图、量化** 等结构，把搜索范围缩小到「很可能包含真邻居」的子集，从而 **大幅降延迟**。

直觉：**不再把整座图书馆每一页都翻一遍，而是先根据索引牌跳到几个书架，再细找**——偶尔漏一本，但大多数时候够快够准。

**工程语境（FAISS 本地 ANN）**：
- 解决什么：把「ANN」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- ANN 和容易混淆的替代方案怎么选？
- 如果去掉 ANN 这一层，最先坏掉的是哪一环？

### Q13. 做 FAISS 本地 ANN 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 FAISS 本地 ANN 全链路。

**通常不在同一层硬做的**（示例）：
- ** GPU 大规模训练式索引调参全书、PQ 乘积量化 bit 级细节、分布式 Milvus 集群、混合 BM25+向量（C4 后续篇）。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

**参考答法（开发向）：**

**答题要点**：
