### Q1. 什么是 RRF？在 RRF 融合排序 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · RRF |

**参考答法（开发向）：**

**RRF**（Reciprocal Rank Fusion，倒数排名融合）：一种把多路检索结果合成一个排序的方法。它不直接比较不同检索器的原始分数，而是看候选在每一路结果里的排名。

直觉：不问“每个裁判打了多少分”，只看“每个裁判把它排第几”。

**工程语境（RRF 融合排序）**：
- 解决什么：把「RRF」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- RRF 和容易混淆的替代方案怎么选？
- 如果去掉 RRF 这一层，最先坏掉的是哪一环？

### Q14. RRF 融合排序 能力要上生产，你会优先保证哪三件事？ {#q14}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 RRF 融合排序 常见风险点：Dense 检索可能返回 cosine 分数，Sparse 检索返回 BM25 分数。两者分数尺度不同，直接相加很容易让一路结果压倒另一路。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
