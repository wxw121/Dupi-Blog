### Q1. 什么是 知识图谱增强检索？在 知识图谱增强检索 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 知识图谱增强检索 |

**参考答法（开发向）：**

**知识图谱增强检索**（KG-Enhanced Retrieval）：在检索阶段引入 **实体（节点）与关系（边）**，用图遍历、子图匹配或图约束过滤 **缩小/扩展** 向量候选集，再把命中的 chunk 交给生成器。

**工程语境（知识图谱增强检索）**：
- 解决什么：把「知识图谱增强检索」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 知识图谱增强检索 和容易混淆的替代方案怎么选？
- 如果去掉 知识图谱增强检索 这一层，最先坏掉的是哪一环？

### Q6. 做 知识图谱增强检索 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q6}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 知识图谱增强检索 全链路。

**通常不在同一层硬做的**（示例）：
- ** 全量 GraphRAG 社区发现算法细节、知识图谱自动构建 ML 全书、图神经网络嵌入训练、Neo4j 集群运维全书。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q9. 知识图谱增强检索 能力要上生产，你会优先保证哪三件事？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 知识图谱增强检索 常见风险点：「**产假** 与 **年假** 能否连休？」——两实体在向量空间里可能 **都不靠近** 用户原句；

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
