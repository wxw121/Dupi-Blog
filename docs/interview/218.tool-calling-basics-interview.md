### Q1. 你怎么设计 Agent 的工具调用？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 系统设计 / 表述 |

**参考答法（开发向）：**

工具调用有六步生命周期：注册、发现、验证、执行、标准化、记录。 用注册表管理所有工具，每个工具有 Schema、权限、超时配置。 执行前做参数验证和权限检查。 执行时有超时控制。 返回结果标准化（成功/失败 + 错误码）。 每次调用写审计日志。 LLM 根据描述选择。描述要具体，否则选错。 Agent 根据错误码决定：重试、换工具、还是报告用户。 危险操作需审批。所有调用写审计日志。

**常见追问：**

- LLM 怎么选工具？ 把所有工具的 name + description + parameters 给 LLM。
- 工具调用失败怎么办？ 标准化错误返回给 Agent。
- 怎么防止工具被滥用？ 权限分级（auto/confirm/approval/forbidden）。

**参考答法（开发向）：**

**Tool Calling**（工具调用）：模型输出结构化函数名与参数，由执行器调用真实函数。

直觉：像给助理一张办事清单——写明「去办哪件事、带什么材料」。

- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。
