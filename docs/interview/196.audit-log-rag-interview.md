### Q1. 什么是 审计日志？在 RAG 审计日志 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 审计日志 |

**参考答法（开发向）：**

**审计日志**（Audit Log）：面向追责和合规的结构化事件记录。它记录主体、动作、对象、时间、结果和上下文。

**工程语境（RAG 审计日志）**：
- 解决什么：把「审计日志」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 审计日志 和容易混淆的替代方案怎么选？
- 如果去掉 审计日志 这一层，最先坏掉的是哪一环？

### Q2. 如何设计/实现「审计事件的最小可信要素」？（RAG 审计日志） {#q2}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 审计事件的最小可信要素 |

**参考答法（开发向）：**

**背景要点**：企业 RAG 不是个人笔记工具。用户可能上传合同、政策、客户资料和内部工单。系统回答问题时，可能检索到敏感文档，也可能把答案导出给外部人员。出了问题后，团队必须能回答：

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；
2. **组件图**：列出 3～5 个模块及数据流（可手绘）；
3. **关键接口**：同步 API / 消息 / 批处理任务各负责什么；
4. **失败与降级**：超时、空检索、工具失败时的默认策略；
5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

- MVP 版本可以砍掉哪些部分？
- 10x 流量时最先改什么？

### Q6. 生产环境 RAG 审计日志 出现：这一节收束审计日志的边界。审计日志不是“把所有东西都记下来”，而是“把关键动作用稳定 schema 记下来”。… —— 排查思路是什么？ {#q6}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：这一节收束审计日志的边界。审计日志不是“把所有东西都记下来”，而是“把关键动作用稳定 schema 记下来”。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q12. RAG 审计日志 能力要上生产，你会优先保证哪三件事？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 RAG 审计日志 常见风险点：企业 RAG 不是个人笔记工具。用户可能上传合同、政策、客户资料和内部工单。系统回答问题时，可能检索到敏感文档，也可能把答案导出给外部人员。出了问题后，团队必须能回答：

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？

### Q13. 用 2 分钟讲清楚 RAG 审计日志 的技术方案（面向面试官）。 {#q13}

|------|------|

**参考答法（开发向）：**

**30 秒版**：问题背景 → 核心组件 → 一条量化结果。

**2 分钟版**（可按链路讲）：为什么需要审计日志 → 与结构化日志、Trace 的分工 → 触发审计需求的典型场景 → 审计日志是什么

每层补一句：**输入输出 + 失败怎么办**。
避免背章节标题；用「请求进来以后……」的叙事更自然。

**常见追问：**

- 如果面试官只给白板，你会先画哪张图？
- 你最自豪的一次优化是什么？
