### Q1. 什么是 L2 归一化？在 L2 归一化 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · L2 归一化 |

**参考答法（开发向）：**

**L2 归一化**（L2 normalization）：把向量除以其 **L2 范数**（欧氏长度），使结果向量长度为 1，只保留方向信息。

直觉：把每支箭头 **拉成同样长**，再比「指的方向」——这样点积就不会被「谁更长」带偏。

**工程语境（L2 归一化）**：
- 解决什么：把「L2 归一化」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- L2 归一化 和容易混淆的替代方案怎么选？
- 如果去掉 L2 归一化 这一层，最先坏掉的是哪一环？

### Q7. 生产环境 L2 归一化 出现：[ ] 入库与查询调用 **同一** （或同参数 ）… —— 排查思路是什么？ {#q7}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：[ ] 入库与查询调用 **同一** （或同参数 ）

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q9. 做 L2 归一化 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 L2 归一化 全链路。

**通常不在同一层硬做的**（示例）：
- ** FAISS 量化细节、HNSW 图构建、学习型度量训练、完整线性代数证明。模型是否 **内置归一化** 会点到为止，以 **实测范数** 为准。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

| 适用 | 见具体场景约束 | 见具体场景约束 |

### Q13. L2 归一化 能力要上生产，你会优先保证哪三件事？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 L2 归一化 常见风险点：> 工程师：「我们向量库配的是 inner product。」 > 新人：「那检索分和 26 篇讲的余弦 0.87 对不上啊？」 > 工程师：「入库前 normalize 了吗？查询端 normalize 了吗？两端一致吗？」

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
