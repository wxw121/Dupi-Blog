### Q1. 什么是 Prompt？在 System / User / Assistant 提示词角色 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Prompt |

**参考答法（开发向）：**

**Prompt**（提示词）：你喂给模型、用来引导其行为与输出的文本输入（广义上也包括结构化消息）。

直觉：考试卷上的题目说明 + 题目本身；写清楚，答卷才靠谱。

**工程语境（System / User / Assistant 提示词角色）**：
- 解决什么：把「Prompt」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- Prompt 和容易混淆的替代方案怎么选？
- 如果去掉 Prompt 这一层，最先坏掉的是哪一环？

### Q8. 生产环境 System / User / Assistant 提示词角色 出现：1. **只有 user，没有 system**——能跑，但契约难稳定、难版本化。 2. **system 里塞整本知识… —— 排查思路是什么？ {#q8}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：1. **只有 user，没有 system**——能跑，但契约难稳定、难版本化。 2. **system 里塞整本知识库**——窗口与缓存双杀。 3. **多轮不写回 assistant**——表现为失忆。 4. **前端气泡 ≠ 后端 messages**——排障时两头对不上。 5. **把 Few-shot 样板和真实历史混着截断**——示范被砍掉，行为漂移（见第 31 篇）。 6. **以为 role 能替代权限系统**——模型服从 ≠ 数据库行级权限。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q12. 做 System / User / Assistant 提示词角色 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 System / User / Assistant 提示词角色 全链路。

**通常不在同一层硬做的**（示例）：
- ** 工具调用 / Function Calling 全流程、多模态图片消息细节、厂商特有的「开发者消息」变体穷举、完整 Prompt 评测平台。Few-shot 与 Chain-of-Thought 见第 31、32 篇。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q16. System / User / Assistant 提示词角色 能力要上生产，你会优先保证哪三件事？ {#q16}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 System / User / Assistant 提示词角色 常见风险点：对 **Chat Completions**（聊天补全）类接口来说，更准确的画面是：你提交一份 **带角色标签的消息列表**，模型在「接着写下一句助手回复」。角色标签告诉模型：这句话是 **规矩**、是 **用户**，还是 **它自己以前说过的话**。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。
