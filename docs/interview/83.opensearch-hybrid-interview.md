### Q4. 如何设计/实现「稠密检索：kNN query」？（OpenSearch 混合检索入门指南） {#q4}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 稠密检索：kNN query |

**参考答法（开发向）：**

**背景要点**：双路召回不是“跑两次搜索就完事”：两路必须在同一 chunk 主键空间可对齐，filter 语义一致，且各自 top_k 要大到足以让正确证据进入候选池。否则融合层只是在两堆都不完整的列表上做算术，无法弥补单路漏召回。

### Q11. OpenSearch 混合检索入门指南 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 OpenSearch 混合检索入门指南 常见风险点：向量检索擅长语义相似，但对编号、错误码、精确术语不总是稳。BM25 擅长关键词匹配，却不理解同义表达。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
