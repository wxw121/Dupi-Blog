### Q1. 你怎么管理知识库的文档生命周期？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 系统设计 / 表述 |

**参考答法（开发向）：**

我设计了一个知识库管理 Agent。 它监控文档变化，自动触发解析、分块、索引。 用状态机管理文档生命周期（uploaded → parsing → indexed）。 索引失败自动重试（指数退避，最多 3 次）。 定期做一致性检查：清理孤立向量、补全缺失索引。 增量更新：通过内容 hash 检测变化，只重新索引有变化的文档。 没变就跳过，避免无意义的索引开销。 健康检查会定期扫描 failed 文档，尝试恢复。 用 doc_id + version 做向量 ID，避免残留。 每天跑一致性检查，发现不一致立即修复。

**常见追问：**

- 文档更新了怎么处理？ 内容 hash 对比。变了就重新分块、删旧向量、写新向量。
- 索引失败怎么办？ 指数退避重试。3 次都失败就标记 failed，发告警。
- 怎么保证搜索到的是最新内容？ 更新流程是原子的：先删旧向量，再写新向量。
