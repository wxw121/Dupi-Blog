### Q1. 如何设计/实现「和 Dense 检索的关系」？（Metadata 过滤检索） {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 和 Dense 检索的关系 |

**参考答法（开发向）：**

**背景要点**：“财务报销制度”和“人事报销流程”在语义上可能很近，但不是每个人都能看。向量检索如果只按相似度返回 chunk，就可能把越权内容放进 prompt。

5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

### Q4. 如何设计/实现「评测用例模板」？（Metadata 过滤检索） {#q4}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 评测用例模板 |

**参考答法（开发向）：**

**背景要点**：在生产环境里，metadata 过滤不是“加分项”，而是检索 API 的默认契约。很多团队的第一次 RAG 上线只调 embedding 和 top-k，Demo 里答案很漂亮，一接真实租户就发现 A 公司能搜到 B 公司的制度。漏 filter 的代价通常是合规事故，而不是多返几条无关结果。因此从 Day 1 起就应把 filter 与向量 search 写在同一次调用里，并在 code review 里把“检索入口是否必带 filter”列为阻断项。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；

### Q11. Metadata 过滤检索 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Metadata 过滤检索 常见风险点：“财务报销制度”和“人事报销流程”在语义上可能很近，但不是每个人都能看。向量检索如果只按相似度返回 chunk，就可能把越权内容放进 prompt。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
