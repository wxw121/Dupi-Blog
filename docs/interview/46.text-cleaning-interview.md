### Q1. 什么是 文本清洗？在 文本清洗（空白、乱码、页眉页脚） 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 文本清洗 |

**参考答法（开发向）：**

**文本清洗**（Text Cleaning / Normalization）：对原始抽取字符串做 **规则化、去噪、Unicode 规范化**，使其适合 **分块、检索与引用**，而不改变业务语义（在可接受误差内）。

直觉：**洗菜**——泥巴（页眉）、烂叶（乱码）、多余水（空白）弄掉，再下锅炒。

**工程语境（文本清洗（空白、乱码、页眉页脚））**：
- 解决什么：把「文本清洗」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 文本清洗 和容易混淆的替代方案怎么选？
- 如果去掉 文本清洗 这一层，最先坏掉的是哪一环？

### Q11. 文本清洗（空白、乱码、页眉页脚） 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 文本清洗（空白、乱码、页眉页脚） 常见风险点：**文本清洗**（Text Cleaning / Normalization）：对原始抽取字符串做 **规则化、去噪、Unicode 规范化**，使其适合 **分块、检索与引用**，而不改变业务语义（在可接受误差内）。 通俗说：**洗菜**——泥巴（页眉）、烂叶（乱码）、多余水（空白）弄掉，再下锅炒。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

- 如何做成本归因到租户/业务线？
