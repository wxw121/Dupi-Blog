### Q1. 生产环境 LangChain LCEL 入门指南 出现：!Mini-RAG LCEL 如果你只写简单脚本，可以先不学。但如果你阅读 LangChain 新示例、做 RAG 链路… —— 排查思路是什么？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：!Mini-RAG LCEL 如果你只写简单脚本，可以先不学。但如果你阅读 LangChain 新示例、做 RAG 链路组合、使用批处理或流式输出，LCEL 很快会遇到。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q7. LangChain LCEL 入门指南 能力要上生产，你会优先保证哪三件事？ {#q7}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 LangChain LCEL 入门指南 常见风险点：当一条 AI 链路只有两三步时，手写函数调用很直观。随着步骤增加，代码容易变成一长串临时变量：、、、、。变量本身没有错，但流程结构不够显眼。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
