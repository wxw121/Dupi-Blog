### Q1. 什么是 Overlap？在 Overlap 重叠窗口 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Overlap |

**参考答法（开发向）：**

**Overlap**（重叠窗口 / Sliding Window Overlap）：相邻 chunk 之间 **共享一段相同文本**，后一块的开头重复前一块的结尾。

直觉：**像铺地砖留伸缩缝，但故意让相邻砖重叠一截**，避免缝正好踩在关键词上。

**工程语境（Overlap 重叠窗口）**：
- 解决什么：把「Overlap」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- Overlap 和容易混淆的替代方案怎么选？
- 如果去掉 Overlap 这一层，最先坏掉的是哪一环？

### Q5. 如何设计/实现「Overlap 在分块链路中的位置」？（Overlap 重叠窗口） {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · Overlap 在分块链路中的位置 |

**参考答法（开发向）：**

**背景要点**：分块的本质矛盾：**检索要小块**（精准命中），**理解要大块**（上下文够）。固定 且无 overlap 时，每个 chunk 是 **互斥窗口**——边界上的定义、承上启下的半句话、步骤列表的中间一环，很容易 **刚好被切在缝上**。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；
2. **组件图**：列出 3～5 个模块及数据流（可手绘）；
3. **关键接口**：同步 API / 消息 / 批处理任务各负责什么；
4. **失败与降级**：超时、空检索、工具失败时的默认策略；
5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

- MVP 版本可以砍掉哪些部分？
- 10x 流量时最先改什么？

### Q9. 生产环境 Overlap 重叠窗口 出现：Chunk B 含步骤 2 尾部「审批。」+ 步骤 3… —— 排查思路是什么？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：Chunk B 含步骤 2 尾部「审批。」+ 步骤 3

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

### Q12. 做 Overlap 重叠窗口 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 Overlap 重叠窗口 全链路。

**通常不在同一层硬做的**（示例）：
- ** 向量库 dedup 算法细节、Cross-encoder 去重、GraphRAG 实体级 overlap、多模态块对齐。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q16. Overlap 重叠窗口 能力要上生产，你会优先保证哪三件事？ {#q16}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Overlap 重叠窗口 常见风险点：分块的本质矛盾：**检索要小块**（精准命中），**理解要大块**（上下文够）。固定 且无 overlap 时，每个 chunk 是 **互斥窗口**——边界上的定义、承上启下的半句话、步骤列表的中间一环，很容易 **刚好被切在缝上**。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
