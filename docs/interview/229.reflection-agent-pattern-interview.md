### Q1. 什么是 OTA？在 Reflection Agent 模式 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · OTA |

**参考答法（开发向）：**

**OTA**（Observe-Think-Act）：观察环境→推理→执行行动的循环。

直觉：看一眼→想一下→动手→再看结果。

**工程语境（Reflection Agent 模式）**：
- 解决什么：把「OTA」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- OTA 和容易混淆的替代方案怎么选？
- 如果去掉 OTA 这一层，最先坏掉的是哪一环？

### Q12. OTA 和 停止条件 有什么区别？在 Reflection Agent 模式 里如何选型？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 对比题 |
| 难度 | 中等 |
| 考点 | 对比 · OTA vs 停止条件 |

**参考答法（开发向）：**

| 维度 | OTA | 停止条件 |
|------|----------|----------|
| 定义 | 观察环境→推理→执行行动的循环。 | 决定 Agent 何时退出循环的规则。 |
| 适用 | 见具体场景约束 | 见具体场景约束 |

**选型建议**：
- 用 **输入形态**（精确词 vs 语义改写）、**延迟预算**、**运维成本** 三张表说话；
- 给出「默认选谁 + 何时叠加谁」，必要时 Hybrid；
- 用评测集证明，而不是团队偏好。

**常见追问：**

- 能否画一张两路召回合并的时序图？
- 线上如何做 A/B？

### Q13. Reflection Agent 模式 能力要上生产，你会优先保证哪三件事？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Reflection Agent 模式 常见风险点：读下图时，先看「Reflection Agent 模式核心思想」建立直觉。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？

### Q14. 用 2 分钟讲清楚 Reflection Agent 模式 的技术方案（面向面试官）。 {#q14}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 技术表述 |

**参考答法（开发向）：**

**30 秒版**：问题背景 → 核心组件 → 一条量化结果。

**2 分钟版**（可按链路讲）：要不要读 → 它解决什么问题 → Reflection 的核心机制 → 最小示例

每层补一句：**输入输出 + 失败怎么办**。
避免背章节标题；用「请求进来以后……」的叙事更自然。

**常见追问：**

- 如果面试官只给白板，你会先画哪张图？
- 你最自豪的一次优化是什么？
