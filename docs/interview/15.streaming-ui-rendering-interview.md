### Q1. 什么是 流式 UI 渲染？在 逐字显示、中断与用户感知 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 流式 UI 渲染 |

**参考答法（开发向）：**

**流式 UI 渲染**（streaming UI rendering）：把**陆续到达**的文本片段，以**递增方式**呈现在界面上（常见为气泡内文字变长），而不是等全文就绪再一次 或 整段替换。

直觉：字幕**跟着播音逐句上屏**，不是等整部电影配音完再贴一整块字幕。

**工程语境（逐字显示、中断与用户感知）**：
- 解决什么：把「流式 UI 渲染」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 流式 UI 渲染 和容易混淆的替代方案怎么选？
- 如果去掉 流式 UI 渲染 这一层，最先坏掉的是哪一环？

### Q2. 什么是 中断？在 逐字显示、中断与用户感知 相关系统里它承担什么职责？ {#q2}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 中断 |

**参考答法（开发向）：**

**中断**（abort / cancel，中止）：用户在生成过程中点「停止」，前端应**切断仍在进行的网络读流**，并把 UI 从「生成中」切到「已停止 / 可继续输入」；理想情况下后端也停止算力（取决于协议与实现）。

直觉：用户喊「别说了」——既要**闭嘴**（UI），也要尽量**挂电话**（请求）。

**工程语境（逐字显示、中断与用户感知）**：
- 解决什么：把「中断」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 中断 和容易混淆的替代方案怎么选？

### Q5. 生产环境 逐字显示、中断与用户感知 出现：**陷阱 1：等 做聊天** 整段到达才渲染——无流式体验；应用 或 SSE 解析。… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：**陷阱 1：等 做聊天** 整段到达才渲染——无流式体验；应用 或 SSE 解析。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q12. 逐字显示、中断与用户感知 能力要上生产，你会优先保证哪三件事？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 逐字显示、中断与用户感知 常见风险点：典型场景：知识库助手调用大模型，后端要 15 秒才生成完整回答。若前端仍用第三篇那种 ，界面在这 15 秒里只有 **loading 转圈**——用户不知道是在「卡住」还是「正在想」。ChatGPT 类产品把**第一个 token（词元）到达的时间**压到 1 秒内并在屏幕上立刻显示，主观体验就从「慢」变成「正在回答」。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
