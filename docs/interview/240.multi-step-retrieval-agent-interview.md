**考察点**：理解本篇「是什么/为什么/怎么做」主线

**建议回答结构**：
1. **接口/数据**：关键入参、出参、状态字段；

### Q10. 生产环境 多步检索 出现：理解了正确做法之后，让我们看看实际开发中最常犯的错误。这些失败模式每一个都会导致答案质量下降或资源浪费。理解它们的价值不… —— 排查思路是什么？ {#q10}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：理解了正确做法之后，让我们看看实际开发中最常犯的错误。这些失败模式每一个都会导致答案质量下降或资源浪费。理解它们的价值不仅在于"避免犯错"，更在于理解"为什么正确做法是那样的"——很多设计决策正是为了避免这些失败而做出的。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q12. 生产环境 多步检索 出现：这是最常见的错误，也是多步检索要解决的核心问题。开发者在第一步之前就生成了所有查询——但后续查询的内容应该取决于第一步的… —— 排查思路是什么？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：这是最常见的错误，也是多步检索要解决的核心问题。开发者在第一步之前就生成了所有查询——但后续查询的内容应该取决于第一步的结果。在没有结果的情况下猜测后续查询，就像在没有线索的情况下决定搜查所有地点——浪费且可能遗漏。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q17. 多步检索 能力要上生产，你会优先保证哪三件事？ {#q17}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |

结合 多步检索 常见风险点：**演示什么：** 本节最小可运行切片。**环境：** 见文首。**预期：** 控制台打印 demo 输出。

1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
