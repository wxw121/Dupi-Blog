### Q1. 如何设计/实现「前言：观测平台要解决的四件事」？（Langfuse 可观测性） {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 前言：观测平台要解决的四件事 |

**参考答法（开发向）：**

**背景要点**：1. **慢在哪**——检索还是生成？ 2. **错在哪**——解析、切块、检索、胡编？ 3. **花多少**——token 与 embedding 成本？ 4. **哪版配置**——chunk、top_k、reranker 是哪个 171 参数版本？

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；
2. **组件图**：列出 3～5 个模块及数据流（可手绘）；
3. **关键接口**：同步 API / 消息 / 批处理任务各负责什么；
4. **失败与降级**：超时、空检索、工具失败时的默认策略；
5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

- MVP 版本可以砍掉哪些部分？
- 10x 流量时最先改什么？

### Q5. 生产环境 Langfuse 可观测性 出现：下面的错法适合当排障清单看：它们不是语法问题，而是会让评估、追踪或坏例分析失去证据链，最后只能靠猜测定位问题。… —— 排查思路是什么？ {#q5}

|------|------|
| 类型 | 排障题 |

| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：下面的错法适合当排障清单看：它们不是语法问题，而是会让评估、追踪或坏例分析失去证据链，最后只能靠猜测定位问题。

### Q9. 做 Langfuse 可观测性 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 Langfuse 可观测性 全链路。

**通常不在同一层硬做的**（示例）：
- ** K8s 高可用全套、替换 Grafana 基础设施、Langfuse 源码贡献指南。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q12. Langfuse 可观测性 能力要上生产，你会优先保证哪三件事？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Langfuse 可观测性 常见风险点：1. **慢在哪**——检索还是生成？ 2. **错在哪**——解析、切块、检索、胡编？ 3. **花多少**——token 与 embedding 成本？ 4. **哪版配置**——chunk、top_k、reranker 是哪个 171 参数版本？

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
