### Q9. 做 纯文本与编码检测（UTF-8 / GBK） 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 纯文本与编码检测（UTF-8 / GBK） 全链路。

**通常不在同一层硬做的**（示例）：
- ** Unicode 联盟完整标准、各语言 ICU 实现、加密二进制、PDF/DOCX 内部编码（另有专用解析器）。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q12. 纯文本与编码检测（UTF-8 / GBK） 能力要上生产，你会优先保证哪三件事？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 纯文本与编码检测（UTF-8 / GBK） 常见风险点：业务系统导出的 **CSV**（Excel 另存，可能是 GBK）；

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。
