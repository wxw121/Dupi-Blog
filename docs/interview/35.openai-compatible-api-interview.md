### Q9. 生产环境 闭源 LLM API 调用模式（OpenAI 兼容） 出现：1. **把兼容当 100% 一致**——遇怪错先查网关文档与模型支持列表。 2. **开发 Key 打生产流量**——… —— 排查思路是什么？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：1. **把兼容当 100% 一致**——遇怪错先查网关文档与模型支持列表。 2. **开发 Key 打生产流量**——无法审计、无法轮换。 3. **忽略 usage**——成本失控；见 27 篇。 4. **embedding 维度假设不变**——换模型要重建索引。 5. **chat 返回当结构化数据**——要 JSON 就加格式约束并校验解析。 6. **无超时无重试上限**——雪崩时拖垮全站。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q13. 做 闭源 LLM API 调用模式（OpenAI 兼容） 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 闭源 LLM API 调用模式（OpenAI 兼容） 全链路。

**通常不在同一层硬做的**（示例）：
- ** 自研网关源码、Kubernetes 部署、多模型路由完整产品、Function Calling 全链路、各厂商私有参数穷举、完整异步高并发架构（async 细节见路线图 A 轨）。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q17. 闭源 LLM API 调用模式（OpenAI 兼容） 能力要上生产，你会优先保证哪三件事？ {#q17}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 闭源 LLM API 调用模式（OpenAI 兼容） 常见风险点：能跑通，但一上线就踩坑：Key 进了 Git 历史、把 embedding 模型名传给 chat、429 时疯狂重试把账号打封、生产与开发共用同一个 Key 无法轮换。 **API 调用模式** 指的是：你用 **同一套 HTTP 形状**（路径、JSON 字段、鉴权头）去访问 **聊天生成** 与 **向量嵌入** 等服务，并把 **配置、错误、重试、观测** 纳入工程习惯。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。
