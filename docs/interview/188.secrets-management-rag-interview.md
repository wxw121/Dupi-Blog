| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 按服务最小权限矩阵 |

**参考答法（开发向）：**

**背景要点**：初学阶段常见写法是把 API Key 直接放进代码或 。这在本地练习还能接受，但一旦进入团队协作和生产环境，就会带来泄漏风险：代码仓库、Docker 镜像层、日志、前端 bundle、报错堆栈都可能把密钥暴露出去。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；

5. **评测**：离线指标 + 线上 shadow / 金丝雀。

### Q5. 生产环境 RAG 密钥管理 出现：这一节收束密钥管理的边界。密钥管理的目标不是“藏得神秘”，而是减少泄漏面、限制权限、支持轮换和追踪访问。… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：这一节收束密钥管理的边界。密钥管理的目标不是“藏得神秘”，而是减少泄漏面、限制权限、支持轮换和追踪访问。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q11. RAG 密钥管理 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 RAG 密钥管理 常见风险点：初学阶段常见写法是把 API Key 直接放进代码或 。这在本地练习还能接受，但一旦进入团队协作和生产环境，就会带来泄漏风险：代码仓库、Docker 镜像层、日志、前端 bundle、报错堆栈都可能把密钥暴露出去。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
