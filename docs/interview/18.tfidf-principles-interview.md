### Q1. 什么是 信息检索？在 TF-IDF 原理 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 信息检索 |

**参考答法（开发向）：**

**信息检索**（IR，Information Retrieval）：从文档集合里找与需求相关的内容；TF-IDF 是 IR 课本与搜索引擎早期的核心组件之一。

直觉：**图书馆找书** 时，不只看「有没有这个词」，还看「这个词是不是这本书的主题」。

**工程语境（TF-IDF 原理）**：
- 解决什么：把「信息检索」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；

|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 倒排索引 |

**参考答法（开发向）：**

**倒排索引**（inverted index）：每个 term 挂一张 **posting list**（posting 列表），记录「哪些文档包含它、出现几次」。

直觉：**从词出发找文档**，不是从文档出发扫整张表。TF-IDF 的权重可以 **建索引时预计算**，也可以 **查询时按 BM25 公式现场算**——倒排结构是稀疏检索的工程基础，路线图第 27 条会专讲；本篇只需知道 **TF-IDF 是 posting 上的一种打分思想**。

### Q9. 生产环境 TF-IDF 原理 出现：**陷阱 1**：测试集/新文档的 IDF 用训练集统计泄露还好，但 **在线语料扩大** 后 IDF 应 **定期重算… —— 排查思路是什么？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：**陷阱 1**：测试集/新文档的 IDF 用训练集统计泄露还好，但 **在线语料扩大** 后 IDF 应 **定期重算** 或增量更新，否则新词 idf 不对。 **陷阱 2**：查询与文档 **分词不一致**。 **陷阱 3**：把整个超长 PDF 当一篇算 TF——chunk 级索引更贴 RAG。 **陷阱 4**：去掉停用词后「年假」变成「年」「假」——分词错则 TF-IDF 全错。 **陷阱 5**：把 TF-IDF 分数当「语义相关概率」——它只是加权计数，要评测 P@k、MRR。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q16. TF-IDF 原理 能力要上生产，你会优先保证哪三件事？ {#q16}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 TF-IDF 原理 常见风险点：典型场景：内网 3000 份制度 PDF 已切成 chunk 建索引。用户搜「研发部 差旅 住宿标准」——朴素做法是：含这些词的 chunk 越多越好就排越前。结果排第一的却是《员工手册》总则，因为「员工」「公司」「规定」在几乎每篇都出现，**高频但无区分度**的词把真正讲「住宿标准」的段落淹没了。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
