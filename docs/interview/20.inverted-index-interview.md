### Q1. 什么是 倒排索引？在 倒排索引概念 相关系统里它承担什么职责？ {#q1}

|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 倒排索引 |

**参考答法（开发向）：**

**倒排索引**（inverted index）：以 **term（词项）** 为键，值为包含该 term 的 **文档（chunk）列表** 及出现信息（如 tf）的数据结构。

直觉：**字典目录**——查「报销」一页，立刻看到出现在第 3、7、102 号 chunk，各几次。

|------|------|

| 考点 | 工程设计 · 倒排索引的三块积木 |

**参考答法（开发向）：**

**背景要点**：典型场景：制度库 2 万个 chunk，用户搜「年假报销」。朴素做法：循环 2 万次，每次分词、数词、算 BM25——CPU 和延迟都受不了。倒排索引把问题反过来：**先查词典里的「年假」「报销」**，每张表直接列出含该词的 chunk 编号与次数，只在 **候选集合** 上打分排序。

1. **目标与约束**：延迟、准确率、成本、团队规模；

### Q7. 生产环境 倒排索引概念 出现：**陷阱 1**：索引与查询 **analyzer 不一致** → 查不到。 **陷阱 2**：把整篇 PDF 当一个 … —— 排查思路是什么？ {#q7}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：**陷阱 1**：索引与查询 **analyzer 不一致** → 查不到。 **陷阱 2**：把整篇 PDF 当一个 doc_id，|d| 极大，BM25 长度项异常。 **陷阱 3**：以为建了向量库就不需要倒排 → 专有词、条款号常仍需稀疏一路。 **陷阱 4**：手写 dict 不上锁并发写 posting → 生产用 ES/Lucene。 **陷阱 5**：只更新正文不 **reindex** 倒排 → 搜到过期内容或漏新词。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q14. 倒排索引概念 能力要上生产，你会优先保证哪三件事？ {#q14}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 倒排索引概念 常见风险点：典型场景：制度库 2 万个 chunk，用户搜「年假报销」。朴素做法：循环 2 万次，每次分词、数词、算 BM25——CPU 和延迟都受不了。倒排索引把问题反过来：**先查词典里的「年假」「报销」**，每张表直接列出含该词的 chunk 编号与次数，只在 **候选集合** 上打分排序。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
