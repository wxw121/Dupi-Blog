**参考答法（开发向）：**

### Q10. 做 PyMuPDF（fitz） 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q10}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 PyMuPDF（fitz） 全链路。

**通常不在同一层硬做的**（示例）：
- ** PDF 内部对象流语法、渲染成图片的精细参数、JavaScript 动作、完整 OCR 流水线、PDF 编辑合规（红章/legal）。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q13. PyMuPDF（fitz） 能力要上生产，你会优先保证哪三件事？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 PyMuPDF（fitz） 常见风险点：PDF 是 **二进制格式**，内容是绘图指令、字体映射、压缩流——不是给人 的。正确思路是：**用 PDF 库打开 → 逐页 ask「这页有哪些字」→ 拼成 chunk，并记下页码**。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
