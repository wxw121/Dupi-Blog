| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：[ ] 列数与 Excel 源一致（抽检 3 页）

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；

5. **根因与回归**：补集成测试 + 告警阈值。

### Q7. 做 pdfplumber 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q7}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 pdfplumber 全链路。

**通常不在同一层硬做的**（示例）：
- ** Camelot/Tabula 对比实验、深度学习版面分析（LayoutLM 等）、无线表格高级调参、扫描表格 OCR。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q10. pdfplumber 能力要上生产，你会优先保证哪三件事？ {#q10}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 pdfplumber 常见风险点：PDF 里的表格，视觉上对齐；底层往往是 **绝对坐标上的文字块**，未必有「这是第 2 列第 3 行」的语义。PyMuPDF 的 按 **绘制顺序** 吐字，常见结果：

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
