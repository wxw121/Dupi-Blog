### Q9. 生产环境 Source / Page / Section 溯源元数据 出现：下面这些错误看起来只是实现细节，实际会破坏检索、引用、评测或用户体验。读的时候重点看：错法缺少了哪个必要信息，以及正确做… —— 排查思路是什么？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：下面这些错误看起来只是实现细节，实际会破坏检索、引用、评测或用户体验。读的时候重点看：错法缺少了哪个必要信息，以及正确做法如何补上这个缺口。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；

### Q13. 做 Source / Page / Section 溯源元数据 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 Source / Page / Section 溯源元数据 全链路。

**通常不在同一层硬做的**（示例）：
- ** 完整引用卡片 React 组件（F2 轨）、PDF.js 高亮实现、Parent-Document Retriever 代码（C2 **72**）、向量库具体 filter 语法（C4）。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？
