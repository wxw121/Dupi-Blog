| 考点 | 工程设计 · 错：生产暴露 Swagger 无 aut |

### Q3. 生产环境 OpenAPI / Swagger 文档 出现：下面这些错误会让 API 文档从“协作契约”退化成“摆设”。OpenAPI 的价值在于前后端、测试和 SDK 都能复用同… —— 排查思路是什么？ {#q3}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：下面这些错误会让 API 文档从“协作契约”退化成“摆设”。OpenAPI 的价值在于前后端、测试和 SDK 都能复用同一份结构化描述。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q7. OpenAPI / Swagger 文档 能力要上生产，你会优先保证哪三件事？ {#q7}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 OpenAPI / Swagger 文档 常见风险点：SSE 流式 116（OpenAPI 3.1 对 stream 支持需查版本）

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
