### Q5. 生产环境 管理后台日志与评测看板 出现：日志与评测看板会接触问题、回答、检索片段和评测原因，因此不能只按普通后台表格来设计。下面这些问题关系到质量判断是否可信，… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：日志与评测看板会接触问题、回答、检索片段和评测原因，因此不能只按普通后台表格来设计。下面这些问题关系到质量判断是否可信，以及敏感数据是否被过度暴露。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q11. 管理后台日志与评测看板 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 管理后台日志与评测看板 常见风险点：是用户问题本身超出知识库；

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？

### Q12. 用 2 分钟讲清楚 管理后台日志与评测看板 的技术方案（面向面试官）。 {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 技术表述 |

**参考答法（开发向）：**

**30 秒版**：问题背景 → 核心组件 → 一条量化结果。

**2 分钟版**（可按链路讲）：为什么需要日志与评测看板 → 质量回退的典型一周 → 日志、Trace、评测是什么 → 它解决什么问题

每层补一句：**输入输出 + 失败怎么办**。
避免背章节标题；用「请求进来以后……」的叙事更自然。

**常见追问：**

- 如果面试官只给白板，你会先画哪张图？
- 你最自豪的一次优化是什么？
