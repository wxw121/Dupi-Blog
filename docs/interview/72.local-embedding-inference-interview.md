### Q1. 什么是 本地 Embedding 推理？在 本地 Embedding 推理 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 本地 Embedding 推理 |

**参考答法（开发向）：**

**本地 Embedding 推理**（Local Embedding Inference）：在自有服务器或开发机上加载 **开源句向量模型**（如 BGE、E5、GTE），用 **PyTorch / ONNX Runtime** 等执行前向计算，将文本批次转为浮点向量，**不经过第三方 Embedding API**。

直觉：**把「编目员」请进自己机房**——模型权重在你磁盘上，算向量在你进程里完成。

**工程语境（本地 Embedding 推理）**：
- 解决什么：把「本地 Embedding 推理」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 本地 Embedding 推理 和容易混淆的替代方案怎么选？
- 如果去掉 本地 Embedding 推理 这一层，最先坏掉的是哪一环？

### Q11. 做 本地 Embedding 推理 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 本地 Embedding 推理 全链路。

**通常不在同一层硬做的**（示例）：
- ** 模型训练与微调（见 73 篇）、FAISS 索引参数调优（C4）、Kubernetes 大规模调度、完整 MLOps 流水线。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q15. 本地 Embedding 推理 能力要上生产，你会优先保证哪三件事？ {#q15}

|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 本地 Embedding 推理 常见风险点：企业 RAG 的向量化阶段，很多人第一反应是调 **OpenAI / 国内兼容网关** 的 接口——快、稳、不用管 GPU。但真实项目里常出现三类硬约束：

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。
