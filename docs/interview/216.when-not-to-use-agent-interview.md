### Q1. 什么时候不该用 Agent？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 系统设计 / 表述 |

**参考答法（开发向）：**

六类场景不用 Agent： 确定性操作（用 API）、固定流程（用 Workflow）、 实时性要求高（用轻量模型）、强合规（用规则引擎）、 数据量极大（用批处理）、团队没能力维护。 核心原则：用最简单的能解决问题的方案。 Agent 是最后的选择，不是第一选择。 如果 API 能 50ms 搞定，为什么要用 Agent 等 10 秒？ 只有真正需要动态决策的才走 Agent。 这样既满足了"用 Agent"的要求，又不浪费。 需要动态决策吗？四个"是"才用 Agent。

**常见追问：**

- 怎么说服团队不用 Agent？ 用数据：成本对比、延迟对比、可靠性对比。
- 如果老板坚持要用 Agent 呢？ 混合方案：路由层判断，简单的走 API/RAG，
- 怎么判断一个需求是否需要 Agent？ 四个问题：需要 LLM 吗？需要多步吗？步骤固定吗？

### Q2. 什么是 Agent？在 什么时候不要使用 Agent 相关系统里它承担什么职责？ {#q2}

|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Agent |

**参考答法（开发向）：**

**Agent**（智能体）：自主多步执行任务的系统。

直觉：给目标后能自己规划并动手，不是只答一问。

**工程语境（什么时候不要使用 Agent）**：
- 解决什么：把「Agent」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- Agent 和容易混淆的替代方案怎么选？
- 如果去掉 Agent 这一层，最先坏掉的是哪一环？

|------|------|
