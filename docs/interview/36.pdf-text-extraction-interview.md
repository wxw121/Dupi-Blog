### Q1. 什么是 PDF？在 PDF 文本提取 相关系统里它承担什么职责？ {#q1}

|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · PDF |

**参考答法（开发向）：**

**PDF**（Portable Document Format，便携式文档格式）：一种以页面为单位描述文字、图形、图像位置的文件格式，强调跨设备版式一致。

直觉：**电子纸**——像拍照冲印，不像可编辑的笔记本。

- 解决什么：把「PDF」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

- PDF 和容易混淆的替代方案怎么选？

### Q9. 生产环境 PDF 文本提取 出现：左栏读完才该读右栏，但输出成「左1行、右1行、左2行…」；… —— 排查思路是什么？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：左栏读完才该读右栏，但输出成「左1行、右1行、左2行…」；

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q10. 做 PDF 文本提取 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q10}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 PDF 文本提取 全链路。

**通常不在同一层硬做的**（示例）：
- ** 表格结构恢复、复杂版面分析（LayoutLM 等）、OCR 引擎调参、Java PDFBox 企业级方案、扫描 PDF 批量 GPU 流水线（仅指路路线图 62）。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q14. PDF 文本提取 能力要上生产，你会优先保证哪三件事？ {#q14}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 PDF 文本提取 常见风险点：**好消息**：大量企业 PDF 是「可选中复制」的，有 **文本层**，用库能较快抽出字串。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
