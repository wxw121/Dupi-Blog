### Q1. Agent、RAG、Workflow 怎么选？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 系统设计 / 表述 |

**参考答法（开发向）：**

四种形态：API、RAG、Workflow、Agent，复杂度递增。 选型原则：用最简单的能解决问题的。 不需要 LLM → API。一问一答 → RAG。 固定多步 → Workflow。动态决策 → Agent。 实际系统是混合的：路由层根据请求类型分发。 简单查询用 Agent 是 10 秒 + $0.2，用 API 是 50ms + $0。 而且 Agent 有随机性，固定流程不需要随机性。 四个问题问完就知道用哪种。 前端统一接口，后端路由层分发。 降级链：Agent → Workflow → RAG → 模板 → 人工。

**常见追问：**

- 为什么不全部用 Agent？ 成本、延迟、确定性。
- 怎么决定一个需求用哪种？ 决策树：需要 LLM 吗？需要多步吗？步骤固定吗？需要动态决策吗？
- 实际系统怎么组织？ 混合架构 + 统一路由。

| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：后果： 延迟从 50ms 变成 10s 成本从 $0 变成 $0.1 用户体验极差

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。
