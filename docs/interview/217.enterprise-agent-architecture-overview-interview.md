### Q1. 你怎么设计企业级 Agent 架构？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 系统设计 / 表述 |

**参考答法（开发向）：**

五层架构：接入层、编排层、工具层、模型层、基础设施层。 接入层做认证限流，编排层管 Agent 循环， 工具层统一权限和执行，模型层管 LLM 路由和降级， 基础设施层做日志监控审计。 层间通过接口通信，依赖注入组装。 替换模型不影响工具，替换工具不影响编排。 权限在工具层统一拦截，不用每个工具自己做。 传统后端没有"多步决策循环"的概念。 模型层要处理不确定性（降级、缓存、路由）。 但权限和审计不能省。 等团队大了再逐步拆分。

**常见追问：**

- 为什么分五层？ 单一职责。每层只管一件事。
- 和传统后端分层有什么区别？ 多了编排层（Agent 循环）和模型层（LLM 管理）。
- 小团队也要这么分吗？ 不需要。3 人以下可以合并为 2-3 层。

### Q12. 生产环境 企业级 Agent 架构总览 出现：A：看团队规模。 1-2 人：合并为 2-3 层（gateway+orchestrator / tools+model … —— 排查思路是什么？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：A：看团队规模。 1-2 人：合并为 2-3 层（gateway+orchestrator / tools+model / infra） 3-5 人：完整五层，但每层可以是同一个进程内的模块 5+ 人：考虑独立服务

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

| 考点 | 对比 · 网关层 vs 编排层 |

**参考答法（开发向）：**

| 维度 | 网关层 | 编排层 |
|------|----------|----------|
| 定义 | 鉴权、限流、路由的统一入口。 | 驱动 Agent OTA 循环与工具调度的核心。 |
| 适用 | 见具体场景约束 | 见具体场景约束 |

**选型建议**：
- 用 **输入形态**（精确词 vs 语义改写）、**延迟预算**、**运维成本** 三张表说话；
- 给出「默认选谁 + 何时叠加谁」，必要时 Hybrid；
- 用评测集证明，而不是团队偏好。

**常见追问：**

- 能否画一张两路召回合并的时序图？

### Q16. 企业级 Agent 架构总览 能力要上生产，你会优先保证哪三件事？ {#q16}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |

**参考答法（开发向）：**

结合 企业级 Agent 架构总览 常见风险点：读下图时，先看「企业级 Agent 架构总览核心思想」建立直觉。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。
