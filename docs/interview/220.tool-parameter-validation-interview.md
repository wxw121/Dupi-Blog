### Q1. 什么是 Tool Calling？在 工具参数校验 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Tool Calling |

**参考答法（开发向）：**

**Tool Calling**（工具调用）：模型输出结构化函数名与参数。

直觉：像给助理一张办事清单，写明「去办哪件事、带什么材料」。

**工程语境（工具参数校验）**：
- 解决什么：把「Tool Calling」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- Tool Calling 和容易混淆的替代方案怎么选？
- 如果去掉 Tool Calling 这一层，最先坏掉的是哪一环？

### Q13. 工具参数校验 能力要上生产，你会优先保证哪三件事？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 工具参数校验 常见风险点：!工具参数校验核心思想 对照上图：校验分格式/业务/跨字段——越早拦截坏参数，ACT 越安全、重试越有意义。
