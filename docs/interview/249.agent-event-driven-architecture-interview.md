### Q1. 你的 Agent 系统怎么处理异步通信？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 系统设计 / 表述 |

**参考答法（开发向）：**

我们用事件驱动架构。 Agent 的每个状态变化都发布领域事件（TaskSubmitted、ToolCallSucceeded 等）。 事件总线负责路由，订阅者各自处理（状态更新、日志、通知）。 用 Event Sourcing 做状态恢复：不存最终状态，存事件流，回放重建。 好处是解耦、可追溯、可扩展。 后台进程异步投递到消息队列。投递成功后标记已发送。 聚合根 apply 时检查版本号，拒绝旧版本。 事件是异步解耦：A 发事件，B 暂时挂了没关系， 恢复后从队列继续消费。系统是最终一致的。

**常见追问：**

- 事件丢了怎么办？ Outbox 模式：事件和业务数据在同一个事务写入数据库，
- 事件乱序怎么办？ 同一 aggregate 的事件路由到同一分区（Kafka key = task_id）。
- 和直接调用有什么区别？ 直接调用是同步耦合：A 调 B，B 挂了 A 也挂。
