**参考答法（开发向）：**

**现象摘要**：[ ] 固定 hold-out 评测集（≥100 query）

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；

### Q12. 做 Embedding 微调概念 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q12}

|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 Embedding 微调概念 全链路。

**通常不在同一层硬做的**（示例）：
- ** 完整 PyTorch 训练循环、分布式 DeepSpeed 配置、每个 loss 的梯度推导、自动 hard negative 挖掘算法细节。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

结合 Embedding 微调概念 常见风险点：1. 调 chunk 大小（61 篇） 2. 换 Embedding 模型（路线图 78～79） 3. 上混合检索 / rerank（C4） 4. **「我们微调一个吧」**
