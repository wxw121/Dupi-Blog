### Q1. 什么是 Context Window？在 Context Window（上下文窗口） 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Context Window |

**参考答法（开发向）：**

**Context Window**（上下文窗口 / 上下文长度限制）：模型在 **单次推理** 中，能同时处理的输入与输出 token 总量上限（具体计法因厂商略有差异，初学按「输入+输出共享一个大桶」理解即可）。

直觉：**这一趟对话请求，行李箱最多装多少「词块」**。

**工程语境（Context Window（上下文窗口））**：
- 解决什么：把「Context Window」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- Context Window 和容易混淆的替代方案怎么选？
- 如果去掉 Context Window 这一层，最先坏掉的是哪一环？

|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Token |

**参考答法（开发向）：**

**Token**（词元）：模型读写文本的最小计费/计数单位，不等于「一个汉字」或「一个英文单词」。

直觉：行李箱里的 **积木块**；中文常「几字一块」，英文常「一词一块或更碎」——精确数要用对应模型的 tokenizer。

**工程语境（Context Window（上下文窗口））**：

### Q7. 生产环境 Context Window（上下文窗口） 出现：1. **把「上下文窗口」当成「长期记忆」** 窗口是单次（或产品封装的有限会话）可见范围；跨会话仍要靠存储与检索。… —— 排查思路是什么？ {#q7}

|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：1. **把「上下文窗口」当成「长期记忆」** 窗口是单次（或产品封装的有限会话）可见范围；跨会话仍要靠存储与检索。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；

### Q11. 做 Context Window（上下文窗口） 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 Context Window（上下文窗口） 全链路。

**通常不在同一层硬做的**（示例）：
- ** 各厂商 tokenizer 源码、RoPE 数学推导、长上下文训练配方、KV Cache 内核优化、完整对话多轮压缩产品方案。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。
