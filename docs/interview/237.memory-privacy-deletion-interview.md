### Q13. 生产环境 Memory 隐私与删除 出现：理解了正确做法之后，让我们看看实际开发中最常犯的错误。这些失败模式每一个都可能导致隐私事故，了解它们能帮你在代码审查时快… —— 排查思路是什么？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：理解了正确做法之后，让我们看看实际开发中最常犯的错误。这些失败模式每一个都可能导致隐私事故，了解它们能帮你在代码审查时快速识别风险。我把它们按"发现难度"排序——越往后越隐蔽，也越危险。理解这些失败模式的价值不仅在于避免它们，更在于理解"为什么正确做法是那样的"——很多设计决策正是为了避免这些失败而做出的。

**排查顺序**：

3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

### Q14. 生产环境 Memory 隐私与删除 出现：这是最常见的错误，也是最危险的错误，因为它看起来"像做了"但实际上没做完整。开发者写了一个删除接口，执行 ，然后觉得"删… —— 排查思路是什么？ {#q14}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：这是最常见的错误，也是最危险的错误，因为它看起来"像做了"但实际上没做完整。开发者写了一个删除接口，执行 ，然后觉得"删除功能做完了"。但向量索引还能搜到这条数据，缓存还能读到这条数据。用户以为删了，但 Agent 下次对话时仍然可能召回这条"已删除"的记忆。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。
