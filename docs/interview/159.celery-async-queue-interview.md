| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 为什么 RAG 需要任务队列 |

**参考答法（开发向）：**

### Q11. Celery RAG 异步任务队列入门指南 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Celery RAG 异步任务队列入门指南 常见风险点：RAG 索引任务通常包括解析、清洗、切分、embedding、写入 VectorStore。它们耗时长、可能失败、可能需要重试。把这些逻辑放在 Web 请求里，会导致超时和不稳定。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
