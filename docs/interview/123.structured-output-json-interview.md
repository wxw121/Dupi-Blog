### Q1. 如何设计/实现「最小可运行示例」？（结构化输出（JSON Mode）入门指南） {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 最小可运行示例 |

**参考答法（开发向）：**

**背景要点**：自然语言适合给人读，却不适合直接给程序读。人看到“置信度大概比较高”能理解，程序却需要一个明确字段，例如 。只要输出格式不稳定，后面的保存、排序、过滤、前端展示都会变得脆弱。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；

4. **失败与降级**：超时、空检索、工具失败时的默认策略；

### Q3. Q：JSON Mode 和 schema 是一回事吗？ {#q3}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 中等 |
| 考点 | 常见误区 |

**参考答法（开发向）：**

不是。JSON Mode 关注“输出是不是 JSON”；schema 关注“JSON 里有哪些字段、字段是什么类型、哪些字段必填”。实际项目通常两者一起用。

### Q8. 结构化输出（JSON Mode）入门指南 能力要上生产，你会优先保证哪三件事？ {#q8}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 结构化输出（JSON Mode）入门指南 常见风险点：自然语言适合给人读，却不适合直接给程序读。人看到“置信度大概比较高”能理解，程序却需要一个明确字段，例如 。只要输出格式不稳定，后面的保存、排序、过滤、前端展示都会变得脆弱。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
