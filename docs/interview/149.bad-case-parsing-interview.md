### Q1. 如何设计/实现「失败模式地图：对照 36～56」？（Bad Case 归因之解析错误） {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 失败模式地图：对照 36～56 |

**参考答法（开发向）：**

**背景要点**：解析错最难缠之处：**索引「成功」了**——任务状态 ，chunk 数量正常，向量也入库了，但 **字是错的、顺序是错的、表是扁的**。检索只能在海里捞 **已经变形的鱼**。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；
2. **组件图**：列出 3～5 个模块及数据流（可手绘）；
3. **关键接口**：同步 API / 消息 / 批处理任务各负责什么；
4. **失败与降级**：超时、空检索、工具失败时的默认策略；
5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

- MVP 版本可以砍掉哪些部分？
- 10x 流量时最先改什么？

### Q4. 生产环境 Bad Case 归因之解析错误 出现：读下图时，先看「解析失败模式地图」想表达的主线：它把本节的概念关系压缩成一张可对照的图。… —— 排查思路是什么？ {#q4}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：读下图时，先看「解析失败模式地图」想表达的主线：它把本节的概念关系压缩成一张可对照的图。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q8. 做 Bad Case 归因之解析错误 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q8}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 Bad Case 归因之解析错误 全链路。

**通常不在同一层硬做的**（示例）：
- ** 单个解析库 API 大全（见 C1 各工具篇）、OCR 模型训练。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q11. Bad Case 归因之解析错误 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Bad Case 归因之解析错误 常见风险点：解析错最难缠之处：**索引「成功」了**——任务状态 ，chunk 数量正常，向量也入库了，但 **字是错的、顺序是错的、表是扁的**。检索只能在海里捞 **已经变形的鱼**。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？

### Q12. 用 2 分钟讲清楚 Bad Case 归因之解析错误 的技术方案（面向面试官）。 {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 技术表述 |

**参考答法（开发向）：**

**30 秒版**：问题背景 → 核心组件 → 一条量化结果。

**2 分钟版**（可按链路讲）：动手路径 → 解析型 bad case 是什么 → 在 trace 上如何识别 → 固定三步

每层补一句：**输入输出 + 失败怎么办**。
避免背章节标题；用「请求进来以后……」的叙事更自然。

**常见追问：**
