### Q5. 生产环境 Qdrant 向量库与 Payload 过滤 出现：不建议。后期会出现 、、 混用。正确做法是统一字段字典，入库流水线校验必填 payload。… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：不建议。后期会出现 、、 混用。正确做法是统一字段字典，入库流水线校验必填 payload。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q11. Qdrant 向量库与 Payload 过滤 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Qdrant 向量库与 Payload 过滤 常见风险点：企业 RAG 很少是“全库搜一下”这么简单。用户身份、租户、文档版本、语言、权限组都会影响候选 chunk。Qdrant 的 payload 过滤让这些条件能和向量检索一起执行。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
