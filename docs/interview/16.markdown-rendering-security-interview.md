### Q1. 什么是 Markdown 渲染？在 从排版到 XSS 防护 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Markdown 渲染 |

**参考答法（开发向）：**

**Markdown 渲染**（Markdown rendering）：把 Markdown **源码字符串**转成浏览器里的标题、段落、列表、代码块等结构化 UI。

直觉：把「带记号的草稿」变成「读者看得舒服的文章版式」。

**工程语境（从排版到 XSS 防护）**：
- 解决什么：把「Markdown 渲染」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- Markdown 渲染 和容易混淆的替代方案怎么选？
- 如果去掉 Markdown 渲染 这一层，最先坏掉的是哪一环？

### Q5. 生产环境 从排版到 XSS 防护 出现：**陷阱 1**： / 输出 HTML 字符串直接 。 **改**：换 react-markdown，或 HTML 串必… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：**陷阱 1**： / 输出 HTML 字符串直接 。 **改**：换 react-markdown，或 HTML 串必须过 DOMPurify。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？

### Q12. 从排版到 XSS 防护 能力要上生产，你会优先保证哪三件事？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 从排版到 XSS 防护 常见风险点：典型场景：知识库助手第七篇已能流式出字，第八步要上 Markdown——开发搜到「把 Markdown 转 HTML」的库，示例里一行 或 直接输出字符串。本地测模型正常回答没问题；直到安全同事贴进一段：

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
