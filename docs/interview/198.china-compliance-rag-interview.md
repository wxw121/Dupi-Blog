### Q9. 生产环境 等保与 RAG 合规语境 出现：误区背后是把复杂系统简单化：上政务云≠应用不用改 ACL；内网 RAG 仍受个保法约束；偷偷调境外 LLM 在招标与合同… —— 排查思路是什么？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：误区背后是把复杂系统简单化：上政务云≠应用不用改 ACL；内网 RAG 仍受个保法约束；偷偷调境外 LLM 在招标与合同上是技术偏离一票否决；等保≠密评，国密招标要单独 gap。立项时 **法务+产品+工程** 一页纸定性产品形态，避免过度合规或违规上线。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q13. 做 等保与 RAG 合规语境 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 等保与 RAG 合规语境 全链路。

**通常不在同一层硬做的**（示例）：
- ** 等保测评打分表逐条、密评全套、律师出具法律意见书。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？
