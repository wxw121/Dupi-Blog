### Q1. 什么是 死信？在 索引失败重试与死信入门指南 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 死信 |

**参考答法（开发向）：**

**死信**（Dead Letter）：多次处理仍失败、或不适合继续重试的任务。通俗说，它是“自动系统处理不了，需要人工或专门流程看”的失败任务。

**工程语境（索引失败重试与死信入门指南）**：
- 解决什么：把「死信」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 死信 和容易混淆的替代方案怎么选？
- 如果去掉 死信 这一层，最先坏掉的是哪一环？

### Q5. 生产环境 索引失败重试与死信入门指南 出现：后台索引链路依赖很多外部条件。文件可能坏，网络可能抖，模型服务可能限流，向量库可能短暂不可用。如果没有失败处理，任务会卡… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：后台索引链路依赖很多外部条件。文件可能坏，网络可能抖，模型服务可能限流，向量库可能短暂不可用。如果没有失败处理，任务会卡住或丢失，用户只看到“处理中”永远不结束。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q11. 索引失败重试与死信入门指南 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 索引失败重试与死信入门指南 常见风险点：后台索引链路依赖很多外部条件。文件可能坏，网络可能抖，模型服务可能限流，向量库可能短暂不可用。如果没有失败处理，任务会卡住或丢失，用户只看到“处理中”永远不结束。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？

**参考答法（开发向）：**
