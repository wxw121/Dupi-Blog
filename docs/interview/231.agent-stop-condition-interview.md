### Q1. 什么是 OTA？在 Agent 停止条件 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · OTA |

**参考答法（开发向）：**

**OTA**（Observe-Think-Act）：观察环境→推理→执行行动的循环。

直觉：看一眼→想一下→动手→再看结果。

**工程语境（Agent 停止条件）**：
- 解决什么：把「OTA」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- OTA 和容易混淆的替代方案怎么选？
- 如果去掉 OTA 这一层，最先坏掉的是哪一环？

### Q11. OTA 和 停止条件 有什么区别？在 Agent 停止条件 里如何选型？ {#q11}

|------|------|
| 类型 | 对比题 |
| 难度 | 中等 |
| 考点 | 对比 · OTA vs 停止条件 |

**参考答法（开发向）：**

| 维度 | OTA | 停止条件 |
|------|----------|----------|
| 定义 | 观察环境→推理→执行行动的循环。 | 决定 Agent 何时退出循环的规则。 |
| 适用 | 见具体场景约束 | 见具体场景约束 |

**选型建议**：
- 用 **输入形态**（精确词 vs 语义改写）、**延迟预算**、**运维成本** 三张表说话；
- 给出「默认选谁 + 何时叠加谁」，必要时 Hybrid；
- 用评测集证明，而不是团队偏好。

### Q12. Agent 停止条件 能力要上生产，你会优先保证哪三件事？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Agent 停止条件 常见风险点：!Agent 停止条件核心思想 对照上图：停止条件=预算+完成信号——没有上限的循环在生产上等于事故。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
