### Q5. 生产环境 pgvector 与 Postgres 一体化 RAG 指南 出现：生产翻车很少是单点神秘 bug，多半是维度、filter、索引或模型版本有一处悄悄漂移。下面 FAQ 按发生频率排列——… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：生产翻车很少是单点神秘 bug，多半是维度、filter、索引或模型版本有一处悄悄漂移。下面 FAQ 按发生频率排列——建表插入、查询变慢、混模型，每条都对应可操作的检查清单，而不是泛泛的“再试试重启”。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q11. pgvector 与 Postgres 一体化 RAG 指南 能力要上生产，你会优先保证哪三件事？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 pgvector 与 Postgres 一体化 RAG 指南 常见风险点：很多企业已经有 Postgres：用户、文档、权限、审计都在里面。如果 RAG 系统再额外引入一个向量数据库，就会多一套部署、备份、权限同步和排障链路。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
