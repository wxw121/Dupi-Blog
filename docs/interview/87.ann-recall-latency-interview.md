### Q1. 什么是 索引评测？在 ANN 召回率与延迟评测指南 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 索引评测 |

**参考答法（开发向）：**

**索引评测**（本篇重点）：pred 是 ANN top-k，gold 是 Flat top-k，看重叠率——衡量“近似索引漏了多少精确近邻”。**业务评测**：gold 是人工标注的“应命中 chunk_id”，pred 是检索 top-k——衡量“正确证据有没有进候选”。两者可一起做：索引 recall 低时，业务 recall 往往也低；索引 recall 高但业务仍差，就要查 embedding 或 chunk 切分。

**工程语境（ANN 召回率与延迟评测指南）**：
- 解决什么：把「索引评测」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 索引评测 和容易混淆的替代方案怎么选？
- 如果去掉 索引评测 这一层，最先坏掉的是哪一环？

### Q6. 生产环境 ANN 召回率与延迟评测指南 出现：ANN 评测 FAQ 围绕“能否只看延迟”“query 集怎么选”“子集 gold 是否够用”。核心原则不变：**索引参… —— 排查思路是什么？ {#q6}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：ANN 评测 FAQ 围绕“能否只看延迟”“query 集怎么选”“子集 gold 是否够用”。核心原则不变：**索引参数变更 = 检索行为变更 = 必须回归**。下面条目含排错速查，便于与线上日志对照。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q12. ANN 召回率与延迟评测指南 能力要上生产，你会优先保证哪三件事？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 ANN 召回率与延迟评测指南 常见风险点：HNSW、IVF 这类索引会跳过一部分候选来换速度。跳过多少、是否影响答案质量，必须用指标说话。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
