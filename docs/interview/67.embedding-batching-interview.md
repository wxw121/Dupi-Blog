### Q1. 什么是 批量 Embedding？在 批量 Embedding 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 批量 Embedding |

**参考答法（开发向）：**

**批量 Embedding**（batching）：一次请求塞多条文本，换吞吐、控内存、配重试。这篇是 企业 RAG 路线图 **C3 向量化第七篇**（路线图第 **84** 条），定位 **地基篇**：讲清 **怎么批**、**batch_size 怎么选**、**吞吐 vs 延迟 vs 内存** 三角，以及 **OpenAI API** 与 **sentence-transformers 本地推理** 的可跑示例。前置：25 Embedding、66 L2 归一化（批量后常接矩阵归一化）。

**工程语境（批量 Embedding）**：
- 解决什么：把「批量 Embedding」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 批量 Embedding 和容易混淆的替代方案怎么选？
- 如果去掉 批量 Embedding 这一层，最先坏掉的是哪一环？

|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · batch_size |

**参考答法（开发向）：**

**batch_size**（批大小）：单次请求送入模型的 **文本条数**（或等价 token 包）。

### Q3. 如何设计/实现「前言：逐条 embed 是索引任务的敌人」？（批量 Embedding） {#q3}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 前言：逐条 embed 是索引任务的敌人 |

**参考答法（开发向）：**

**背景要点**：十万 chunk 就是十万次 HTTP——**索引要跑一整天**，中途任意网络抖动还要从头来。更糟的是：云厂商按 **token 计费**，但 **请求次数** 还受 **RPM**（每分钟请求数）限制；逐条调用很容易 **没 embed 多少就先 429**。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；
2. **组件图**：列出 3～5 个模块及数据流（可手绘）；
3. **关键接口**：同步 API / 消息 / 批处理任务各负责什么；
4. **失败与降级**：超时、空检索、工具失败时的默认策略；
5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

- MVP 版本可以砍掉哪些部分？
- 10x 流量时最先改什么？

### Q9. 做 批量 Embedding 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 批量 Embedding 全链路。

**通常不在同一层硬做的**（示例）：
- ** 分布式 Spark 集群、专用 embedding 训练、各云厂商完整配额表（以文档为准）、GPU 多卡并行拓扑。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q13. 批量 Embedding 能力要上生产，你会优先保证哪三件事？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 批量 Embedding 常见风险点：十万 chunk 就是十万次 HTTP——**索引要跑一整天**，中途任意网络抖动还要从头来。更糟的是：云厂商按 **token 计费**，但 **请求次数** 还受 **RPM**（每分钟请求数）限制；逐条调用很容易 **没 embed 多少就先 429**。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
