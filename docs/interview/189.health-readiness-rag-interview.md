|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · FastAPI 最小实现 |

**参考答法（开发向）：**

**背景要点**：在生产编排里，这两个端点触发**完全不同的运维动作**： 失败通常导致容器重启； 失败通常导致暂时摘流、不接新请求。公网 Ingress 可对 限制内网访问，避免攻击者探测依赖拓扑。响应契约应稳定：health 返回极简 JSON，ready 失败返回 503 与各组件布尔状态，不要暴露内网 IP 或完整异常栈。

### Q5. 生产环境 健康检查 /health /ready 出现：Kubernetes 里用 sidecar 暴露轻量 ；… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：Kubernetes 里用 sidecar 暴露轻量 ；

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q8. 健康检查 /health /ready 能力要上生产，你会优先保证哪三件事？ {#q8}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 健康检查 /health /ready 常见风险点：**进程是否活着**：程序有没有卡死、崩溃、退出；

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
