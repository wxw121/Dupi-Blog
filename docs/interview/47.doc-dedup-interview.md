### Q1. 什么是 精确去重？在 文档去重（Hash / SimHash） 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 精确去重 |

**参考答法（开发向）：**

**精确去重**（Exact deduplication）：字节或规范化全文 **完全一致** 才判重复，常用 **SHA-256** 等密码学 hash。

直觉：**双胞胎要 DNA 每个碱基都一样才算同一人**。

**工程语境（文档去重（Hash / SimHash））**：
- 解决什么：把「精确去重」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 精确去重 和容易混淆的替代方案怎么选？
- 如果去掉 精确去重 这一层，最先坏掉的是哪一环？

### Q4. 如何设计/实现「最小实战：SHA-256 与 SimHash」？（文档去重（Hash / SimHash）） {#q4}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 最小实战：SHA-256 与 SimHa |

**参考答法（开发向）：**

**背景要点**：1. **检索**：近重复 chunk **embedding 极似**，挤占 Top-K，**多样性丧失**。 2. **生成**：模型收到 **五段同一政策**，可能 **合并错版本**（旧版试用期 3 月 vs 新版 6 月）。 3. **引用**：Grounding（34）指向 **三个文件名**，用户不信。 4. **成本**：重复 chunk 重复算 embedding 费、重复进长上下文（28）。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；
2. **组件图**：列出 3～5 个模块及数据流（可手绘）；
3. **关键接口**：同步 API / 消息 / 批处理任务各负责什么；
4. **失败与降级**：超时、空检索、工具失败时的默认策略；
5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

- MVP 版本可以砍掉哪些部分？
- 10x 流量时最先改什么？

### Q11. 做 文档去重（Hash / SimHash） 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 文档去重（Hash / SimHash） 全链路。

**通常不在同一层硬做的**（示例）：
- ** 向量库内 **检索结果去重**（路线图 **123**）、分布式 MinHash LSH 集群、加密 hash 合规、区块链存证。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 文档去重（Hash / SimHash） 常见风险点：1. **检索**：近重复 chunk **embedding 极似**，挤占 Top-K，**多样性丧失**。 2. **生成**：模型收到 **五段同一政策**，可能 **合并错版本**（旧版试用期 3 月 vs 新版 6 月）。 3. **引用**：Grounding（34）指向 **三个文件名**，用户不信。 4. **成本**：重复 chunk 重复算 embedding 费、重复进长上下文（28）。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
