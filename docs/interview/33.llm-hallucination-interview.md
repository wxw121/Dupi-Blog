### Q1. 什么是 幻觉？在 幻觉（Hallucination）成因 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 幻觉 |

**参考答法（开发向）：**

**幻觉**（Hallucination，在 LLM 语境）：模型生成的内容在流畅性、自信度上像真实陈述，但与事实、给定资料或可核验来源 **不一致或无法核验**。

直觉：**一本正经地胡说**——不是随机乱码，而是「假得像样」。

**工程语境（幻觉（Hallucination）成因）**：
- 解决什么：把「幻觉」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 幻觉 和容易混淆的替代方案怎么选？
- 如果去掉 幻觉 这一层，最先坏掉的是哪一环？

### Q3. 如何设计/实现「检索空或错，仍硬答」？（幻觉（Hallucination）成因） {#q3}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 检索空或错，仍硬答 |

**参考答法（开发向）：**

**背景要点**：错别字机器人大家一眼能识破。可怕的是：语气镇定、条目清晰、还写「根据公司规定」——内容却是 **凭空续写** 出来的。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；
2. **组件图**：列出 3～5 个模块及数据流（可手绘）；
3. **关键接口**：同步 API / 消息 / 批处理任务各负责什么；
4. **失败与降级**：超时、空检索、工具失败时的默认策略；
5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

- 10x 流量时最先改什么？

### Q5. 生产环境 幻觉（Hallucination）成因 出现：1. **用更强模型替代验收** → 强模型胡编写得更像真。 2. **只看用户满意度** → 用户可能被流畅度说服。 … —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：1. **用更强模型替代验收** → 强模型胡编写得更像真。 2. **只看用户满意度** → 用户可能被流畅度说服。 3. **RAG 后不再做拒答** → 空检索仍会编。 4. **伪造引用格式** → 比不引用更危险。 5. **把 CoT 当抗幻觉银弹** → 步骤漂亮也可能自我说服（见第 32 篇）。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q12. 幻觉（Hallucination）成因 能力要上生产，你会优先保证哪三件事？ {#q12}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 幻觉（Hallucination）成因 常见风险点：错别字机器人大家一眼能识破。可怕的是：语气镇定、条目清晰、还写「根据公司规定」——内容却是 **凭空续写** 出来的。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
