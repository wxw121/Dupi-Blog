### Q1. 什么是 Self-Attention？在 Self-Attention（自注意力） 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Self-Attention |

**参考答法（开发向）：**

**Self-Attention**（自注意力）：一种让序列中 **每个位置** 根据与其他位置的相关性，**加权混合** 他人信息，从而得到新表示的机制。

直觉：开小组会时，每个人发言前先扫一眼全场——谁和我话题相关，我就多听谁几句，再整理成自己的新理解。

**工程语境（Self-Attention（自注意力））**：
- 解决什么：把「Self-Attention」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- Self-Attention 和容易混淆的替代方案怎么选？
- 如果去掉 Self-Attention 这一层，最先坏掉的是哪一环？

### Q5. 如何设计/实现「和「检索」别混」？（Self-Attention（自注意力）） {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 设计题 |
| 难度 | 中等 |
| 考点 | 工程设计 · 和「检索」别混 |

**参考答法（开发向）：**

**背景要点**：读到「银行」两个字，人会下意识问：这是 **金融机构**，还是 **河岸**？你靠的是 **前后文**——「去银行开户」和「河岸边的银行」会激活不同理解。

**设计回答框架**：
1. **目标与约束**：延迟、准确率、成本、团队规模；
2. **组件图**：列出 3～5 个模块及数据流（可手绘）；
3. **关键接口**：同步 API / 消息 / 批处理任务各负责什么；
4. **失败与降级**：超时、空检索、工具失败时的默认策略；
5. **评测**：离线指标 + 线上 shadow / 金丝雀。

**常见追问：**

- MVP 版本可以砍掉哪些部分？
- 10x 流量时最先改什么？

### Q14. Self-Attention（自注意力） 能力要上生产，你会优先保证哪三件事？ {#q14}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Self-Attention（自注意力） 常见风险点：读到「银行」两个字，人会下意识问：这是 **金融机构**，还是 **河岸**？你靠的是 **前后文**——「去银行开户」和「河岸边的银行」会激活不同理解。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
