### Q1. 什么是 引用？在 引用卡片 UI 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 引用 |

**参考答法（开发向）：**

**引用**（citation）：答案里标出的资料来源。

直觉：像论文里的参考文献，告诉读者“这句话是从哪里来的”。

**工程语境（引用卡片 UI）**：
- 解决什么：把「引用」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 引用 和容易混淆的替代方案怎么选？
- 如果去掉 引用 这一层，最先坏掉的是哪一环？

### Q2. 生产环境 引用卡片 UI 出现：不要伪造链接。可以显示标题和片段，并标注“当前不可打开原文”。… —— 排查思路是什么？ {#q2}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：不要伪造链接。可以显示标题和片段，并标注“当前不可打开原文”。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q6. 引用卡片 UI 能力要上生产，你会优先保证哪三件事？ {#q6}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 引用卡片 UI 常见风险点：RAG 的卖点是“基于资料回答”。但如果页面只显示答案，不显示来源，用户仍然无法核验。引用卡片让用户可以从答案跳回原文，检查模型有没有误解资料。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
