### Q1. 什么是 文档版本管理？在 文档版本管理 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 文档版本管理 |

**参考答法（开发向）：**

**文档版本管理**（Document Versioning）：为同一逻辑文档的多次修订保留 **可区分的版本标识**，并在索引、检索、引用链路中一致使用。

直觉：**同本书的不同印次要有编号**，不能书架上只留最后一本却假装从没换过。

**工程语境（文档版本管理）**：
- 解决什么：把「文档版本管理」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 文档版本管理 和容易混淆的替代方案怎么选？
- 如果去掉 文档版本管理 这一层，最先坏掉的是哪一环？

### Q9. 生产环境 文档版本管理 出现：1. **把版本等同于文件路径** —— 路径会变，逻辑文档不变。 2. **版本号从 UI 手工填** —— 易跳号、… —— 排查思路是什么？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：1. **把版本等同于文件路径** —— 路径会变，逻辑文档不变。 2. **版本号从 UI 手工填** —— 易跳号、重复，应用规则或业务 API 下发。 3. **只版本化 PDF，不版本化 MD** —— Wiki 同步同样会改版。 4. **忽略「失效日」** —— 仅有 没有 ，并行有效期会糊。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q13. 做 文档版本管理 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 文档版本管理 全链路。

**通常不在同一层硬做的**（示例）：
- ** Git 式分支合并、Office 自带修订追踪解析、多租户权限模型、完整 CMIS 企业内容管理。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 文档版本管理 常见风险点：上线第一周，HR 上传 ；第三周法务修订后 **同名覆盖**；第五周又改了一版。你的向量库里如果只有「当前文件内容」，会出现三类尴尬：

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
