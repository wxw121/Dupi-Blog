### Q1. 你怎么设计一个运维 Agent？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 综合题 |
| 难度 | 高频 |
| 考点 | 系统设计 / 表述 |

**参考答法（开发向）：**

核心是"诊断推理链 + 安全执行"。 告警触发后，Agent 按步骤诊断：检查资源、检查变更、检查依赖。 匹配已知故障模式，确定根因。 修复操作分四级：只读自动、低风险自动、中风险审批、高风险禁止。 每步操作有回滚点，修复后自动验证。 不确定就升级给人，宁可多升级不能乱操作。 生产环境只有只读权限，操作需审批。 所有命令审计，禁止 sudo。 去重：相同 source + message 只处理一次。 聚合：汇总后发一条摘要。 安全测试：危险命令 100% 拦截。

**常见追问：**

- 怎么防止 Agent 搞破坏？ 命令白名单 + 危险模式黑名单。
- 告警风暴怎么处理？ 滑动窗口检测：60 秒内 > 10 条就抑制。
- 怎么评测效果？ MTTR、自动解决率、误判率、回滚触发次数。
