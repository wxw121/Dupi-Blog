### Q1. 什么是 Dense Retrieval？在 Dense Retrieval 稠密检索 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Dense Retrieval |

**参考答法（开发向）：**

**Dense Retrieval**（稠密检索）：把用户问题和文档片段都变成向量，再按向量相似度找最相关的片段。

直觉：它不是看两个句子有没有相同关键词，而是看它们表达的意思像不像。

**工程语境（Dense Retrieval 稠密检索）**：
- 解决什么：把「Dense Retrieval」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- Dense Retrieval 和容易混淆的替代方案怎么选？

### Q15. Dense Retrieval 稠密检索 能力要上生产，你会优先保证哪三件事？ {#q15}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Dense Retrieval 稠密检索 常见风险点：关键词检索要求用户问法和文档写法尽量一致。文档写的是“住宿费报销上限”，用户问“出差住酒店最多能报多少”，传统关键词可能命中不稳，因为两边没有完全相同的词。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。
