### Q5. 生产环境 Chain-of-Thought（思维链）了解指南 出现：1. **把 CoT 当幻觉特效药**——长推理可能加重自我说服。 2. **与窗口抢预算**——资料被推理挤掉，得不偿… —— 排查思路是什么？ {#q5}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：1. **把 CoT 当幻觉特效药**——长推理可能加重自我说服。 2. **与窗口抢预算**——资料被推理挤掉，得不偿失。 3. **面试背「CoT 一定涨点」**——表述为「常用于多步推理，需评测」。 4. **忽略产品展示策略**——对客暴露内部推理。 5. **和 Agent 规划混淆**——工具调用多步 ≠ 文本 CoT（相关但不是同一章）。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q9. 做 Chain-of-Thought（思维链）了解指南 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q9}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 Chain-of-Thought（思维链）了解指南 全链路。

**通常不在同一层硬做的**（示例）：
- ** 训练期的过程监督、o1 类「内置长思考」产品的内部实现、Tree-of-Thoughts 实装、完整 Agent 规划框架。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？
