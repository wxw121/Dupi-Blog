### Q1. 什么是 周一例会剧本？在 LangSmith 链路追踪 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · 周一例会剧本 |

**参考答法（开发向）：**

**周一例会剧本**（30 分钟）：(1) 过去 7 天 error rate；(2) P95 检索延迟；(3) 抽 5 条用户点踩 trace；(4) 用 149～152 树归因；(5) 对齐本周 170 A/B 是否冲突。

**工程语境（LangSmith 链路追踪）**：
- 解决什么：把「周一例会剧本」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- 周一例会剧本 和容易混淆的替代方案怎么选？
- 如果去掉 周一例会剧本 这一层，最先坏掉的是哪一环？

**参考答法（开发向）：**

### Q10. 做 LangSmith 链路追踪 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q10}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 LangSmith 链路追踪 全链路。

**通常不在同一层硬做的**（示例）：
- ** LangSmith 计费细则全文、替代 Datadog 基础设施监控、非 LangChain 框架的每一行 SDK。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q13. LangSmith 链路追踪 能力要上生产，你会优先保证哪三件事？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 LangSmith 链路追踪 常见风险点：客服：「第 3 条引用打开是空白。」

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
