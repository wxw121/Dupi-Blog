### Q1. 什么是 Chunk Size？在 Chunk Size 调参 Trade-off 相关系统里它承担什么职责？ {#q1}

|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · Chunk Size |

**参考答法（开发向）：**

**Chunk Size**（块大小）：单个检索单元允许的目标长度，常用 **token 数** 或 **字符数** 表示。

直觉：**向量库里「一张卡片」有多厚**。

- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- Chunk Size 和容易混淆的替代方案怎么选？
- 如果去掉 Chunk Size 这一层，最先坏掉的是哪一环？

### Q7. 生产环境 Chunk Size 调参 Trade-off 出现：FAQ 的天然边界是“一问一答”。这类文档通常不需要很大的 chunk，重点是保持一条问答语义完整。… —— 排查思路是什么？ {#q7}

| 维度 | 说明 |
|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：FAQ 的天然边界是“一问一答”。这类文档通常不需要很大的 chunk，重点是保持一条问答语义完整。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

**常见追问：**

- 如何写一份给 on-call 的 runbook？
- 哪些信息必须打进结构化日志？

### Q11. 做 Chunk Size 调参 Trade-off 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q11}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 Chunk Size 调参 Trade-off 全链路。

**通常不在同一层硬做的**（示例）：
- ** 神经架构搜索自动 chunk、多粒度 hierarchical index 实现、ColBERT token 级检索、生产级 AutoML 调参平台。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q14. Chunk Size 调参 Trade-off 能力要上生产，你会优先保证哪三件事？ {#q14}

|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 Chunk Size 调参 Trade-off 常见风险点：**Chunk Size**（块大小）：单个检索单元允许的目标长度，常用 **token 数** 或 **字符数** 表示。 通俗说：**向量库里「一张卡片」有多厚**。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；

3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。
