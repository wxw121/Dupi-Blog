### Q1. 什么是 HTML DOM 分块？在 HTML DOM 分块 相关系统里它承担什么职责？ {#q1}

| 维度 | 说明 |
|------|------|
| 类型 | 概念题 |
| 难度 | 基础 |
| 考点 | 核心概念 · HTML DOM 分块 |

**参考答法（开发向）：**

**HTML DOM 分块**（HTML DOM Chunking）：在 **正文抽取** 得到的 DOM 子树（通常是 / 根）上，按 **语义区块**—— 元素或 / 标题边界——切分出文本块，并保证 、、/ 等结构 **不被拦腰截断**。

直觉：**先抠出文章主体，再沿 或小 的边界切蛋糕，而不是把整页文字粘成一串再数 500 字**。

**工程语境（HTML DOM 分块）**：
- 解决什么：把「HTML DOM 分块」讲清楚时，要落到 **输入/输出、放在链路哪一层、失败时怎么办**；
- 常见误用：只会背定义，说不出和相邻组件的分工；
- 加分项：举一个线上或 demo 中的真实调用点（接口、配置项、监控指标）。

**常见追问：**

- HTML DOM 分块 和容易混淆的替代方案怎么选？

### Q9. 生产环境 HTML DOM 分块 出现：列对齐关系（虽 embedding 不敏感，但 **整表语义** 需要同行）。… —— 排查思路是什么？ {#q9}

|------|------|
| 类型 | 排障题 |
| 难度 | 中等 |
| 考点 | 线上排障 |

**参考答法（开发向）：**

**现象摘要**：列对齐关系（虽 embedding 不敏感，但 **整表语义** 需要同行）。

**排查顺序**：
1. **范围**：影响面、开始时间、是否可回滚；
2. **证据链**：请求 ID → 各 hop 日志（网关 / 应用 / 向量库 / 模型 / 工具）；
3. **分层假设**：数据污染、配置变更、依赖超时、逻辑 bug——每次只验证一个；
4. **止血**：降级（缓存答案、缩小 top_k、关闭非关键工具）、限流；
5. **根因与回归**：补集成测试 + 告警阈值。

### Q10. 做 HTML DOM 分块 时，哪些能力应在当前服务内实现，哪些应下沉到专用组件或另开服务？ {#q10}

| 维度 | 说明 |
|------|------|
| 类型 | 架构边界 |
| 难度 | 中等 |
| 考点 | 架构分层 |

**参考答法（开发向）：**

考察 **分层与职责单一**，避免一个服务包揽 HTML DOM 分块 全链路。

**通常不在同一层硬做的**（示例）：
- ** 完整爬虫合规、Playwright 反爬、CSS 选择器大全、Parent-Document（见 65 篇）。

**答题要点**：
- 当前层只保留 **决策 + 编排 + 领域状态**；
- IO 密集（向量库、对象存储、消息队列）通过稳定接口调用；
- 说清楚 **同步调用 vs 异步任务** 的切分依据（延迟预算、失败重试）。

**常见追问：**

- 团队很小、没有平台组时，边界会不会变？怎么避免过度拆分？

### Q13. HTML DOM 分块 能力要上生产，你会优先保证哪三件事？ {#q13}

| 维度 | 说明 |
|------|------|
| 类型 | 生产化 |
| 难度 | 高频 |
| 考点 | 生产落地 |

**参考答法（开发向）：**

结合 HTML DOM 分块 常见风险点：**HTML DOM 分块**（HTML DOM Chunking）：在 **正文抽取** 得到的 DOM 子树（通常是 / 根）上，按 **语义区块**—— 元素或 / 标题边界——切分出文本块，并保证 、、/ 等结构 **不被拦腰截断**。 通俗说：**先抠出文章主体，再沿 或小 的边界切蛋糕，而不是把整页文字粘成一串再数 500 字**。

**推荐三件事**：
1. **SLO 与降级**：定义 P95/P99、错误预算；检索失败/模型超时时的兜底路径；
2. **可观测**：trace_id 贯穿；记录检索命中、token、工具调用、人工介入；
3. **变更安全**：配置与 Prompt 版本化；灰度 + 自动回滚条件；回归评测门禁。

面试时用 **一个真实指标** 收尾（如 citation 准确率、empty retrieval 率）。

**常见追问：**

- 如何做成本归因到租户/业务线？
- on-call 值班最需要哪三张大盘？
